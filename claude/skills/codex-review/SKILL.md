# codex-review：公開前の Codex レビュー

**checker の機械チェックが通ったあと**に行う。順序は checker → codex-review → 公開。

## 手順

1. **準備**：レビュー対象のファイル/ディレクトリと、見てほしい観点（目的・読者・懸念）を決める。
2. **Codex の有無を確認**：`command -v codex`。無ければ手順 7（代替）へ。
3. **依頼文を作る**（日本語）：対象、目的、読者、見てほしい観点（誤り・抜け・表現・セキュリティ・実名/秘密情報の混入・アクセシビリティ）、出力形式（重大度順の箇条書き、場所と直し方つき）。
4. **実行**（読み取り専用）：

   ```bash
   codex exec --sandbox read-only "<レビュー依頼>"
   ```

   - `--sandbox read-only` を必ず付ける（Codex にファイルを書き換えさせない）。
   - OPENAI_API_KEY などは skills/.env をスクリプト/Codex 側が読む。**Claude は .env を読まない。**
   - 対象が大きい場合は、ファイルを分けて複数回に分ける。
5. **指摘を一覧化**：番号・場所・内容・重大度の表にする。
6. **判断 → 修正 → 再確認**：各指摘を「直す／直さない（理由）／要相談」に分類。直すものは builder で修正し、修正後に再度 codex exec（または checker）で確認する。人の判断が要るものは人に聞く。
7. **代替**：Codex が使えない／失敗した場合は reviewer エージェントに同じ観点で依頼し、その旨を報告に書く。

## 注意

- Codex の指摘は鵜呑みにしない。事実確認が要るものは根拠を確かめる。
- レビューに渡す内容に秘密情報（APIキー、.env、個人情報）を含めない。
- 結果は「指摘件数／直した件数／見送った件数と理由」で報告する。
