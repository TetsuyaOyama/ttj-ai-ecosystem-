この章で分かること

  1. ツールの利用で、モデルが道具を実行するのではないことを説明できる。
  2. tool_use と tool_result のやり取りを、順に言える。
  3. 自分で動かす道具（クライアントツール）と、Anthropic 側で動く道具（サーバーツール）を区別できる。

前提：第 04 章（messages）、第 07 章（stop_reason）。

ツールの利用とは

モデルは、文章を作ることは得意ですが、あなたの会社の在庫表を見に行くことはできません。そこで、道具（ツール）の名前と使い方を、リクエストに書いて渡します。モデルは、必要だと判断すると、「この道具を、この引数で使ってほしい」という依頼を返します。道具を実際に動かすのは、あなたのプログラムです。結果をモデルに返すと、モデルはそれを材料に、最後の答えを作ります（出典：Tool use overview、2026 年 11 月 18 日確認）。

一番大事な点

モデルは、道具を呼ぶ「依頼書」を書くだけです。実行するかどうか、何を許すかは、あなたのコードが決めます。第 13 章の安全の話は、ここが出発点です。

流れを、順に動かして確かめる

次の図は、在庫を調べる道具を使う 1 往復です（例は架空）。ステップを進めると、各段階でやり取りされる中身が見えます。

道具の定義と、やり取りの部品

道具は、tools の配列に、name（名前）、description（説明）、input_schema（引数の形を表す JSON Schema）で書きます。description は、モデルが「いつ使うか」を決める手がかりなので、丁寧に書きます。strict: true を付けると、呼び出しの入力が schema に合うことを保証できます。

コードで書くと

次の例は、上の流れをそのままコードにしたものです。道具の本体（get_stock）は、あなたの側にあり、表は説明用の架空のものです。繰り返しには、回数の上限を置いています。このコードは、構文の検査だけをして、API を呼んで動かしてはいません。

import anthropic

client = anthropic.Anthropic()

tools = [
    {
        "name": "get_stock",
        "description": "商品コードを受け取り、在庫の数を返す。在庫の数だけを調べる道具で、注文はできない。",
        "input_schema": {
            "type": "object",
            "properties": {"code": {"type": "string", "description": "商品コード（例：A-100）"}},
            "required": ["code"],
        },
    }
]


def get_stock(code):
    table = {"A-100": 12, "B-200": 0}  # 説明用の架空の在庫表
    return str(table.get(code, "該当なし"))


messages = [{"role": "user", "content": "A-100 と B-200 の在庫を教えてください。"}]

for _ in range(5):  # 無限に回らないよう、回数に上限を置く
    response = client.messages.create(
        model="claude-haiku-5-5",
        max_tokens=1000,
        tools=tools,
        messages=messages,
    )
    if response.stop_reason != "tool_use":
        break
    messages.append({"role": "assistant", "content": response.content})
    results = []
    for block in response.content:
        if block.type == "tool_use":
            results.append(
                {"type": "tool_result", "tool_use_id": block.id, "content": get_stock(**block.input)}
            )
    messages.append({"role": "user", "content": results})

print("".join(b.text for b in response.content if b.type == "text"))  # 文章のブロックだけをつなげて表示

SDK には、この繰り返しを代わりに行うツールランナーもあります（公式の説明による。ベータ機能の場合があるので、公式で確かめてください）。まず、仕組みが分かるように、自分で書いた形で理解しておくと安心です。

自分で動かす道具と、Anthropic 側で動く道具

tool_choice：使うかどうかを決める

道具を使うかどうかは、tool_choice で指定できます。注意が 1 つあります。「必ず呼ぶ」の指定（any と tool）は、確認日の時点で、Fable 5.2・Opus 5.5・Sonnet 5.5 などのモデルでは使えず、400 エラーになります。そのときは、既定の auto のままにして、strict: true や構造化した出力（第 08 章）を使うよう、公式は案内しています（出典：Define tools）。

つまずきやすい点

つまずきやすい点

1 つ目は、tool_result の置き方です。直前の assistant の発言の直後に、1 つの user メッセージとして置き、tool_result を先に並べます（文章は後）。2 つ目は、失敗の返し方です。実行に失敗したら、is_error: true と、何が起きて次に何を試すとよいかを書いて返します。3 つ目は、繰り返しの上限がないことです。モデルが道具を呼び続けると、費用がかさむので、回数に上限を置きます（第 07 章）。4 つ目は、道具に、強い権限を持たせることです。まずは、読むだけの道具から始めます。
