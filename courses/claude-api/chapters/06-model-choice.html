この章で分かること

  1. 4 つのモデルの位置づけと、API で指定する ID を、表で確かめられる。
  2. モデルを選ぶ基準（性能・速さ・費用・努力量）と、公式が示す 2 つの始め方を説明できる。
  3. 「軽い作業は軽いモデルで」という使い分けを、評価で確かめる考え方を説明できる。

前提：第 05 章（料金の表）。料金の数字はこの章では繰り返さず、第 05 章を見ます。

4 つのモデル

確認日の時点で、公式のモデル一覧は、4 つの最新モデルを挙げています。Claude Fable 5.2、Claude Opus 5.5、Claude Sonnet 5.5、Claude Haiku 5.5 です。API には、モデル ID（文字列）で指定します（出典：Models overview、2026 年 11 月 18 日確認）。

公式のモデル一覧は、多くの仕事の出発点として Opus 5.5 を勧め、要求の厳しい推論や長時間のエージェントの仕事には Fable 5.2 を挙げています。Haiku 5.5 は、最も低い遅延と価格が必要なときの選択肢です（出典：Choosing a model）。

モデル ID は「固定された版」

公式ドキュメントによると、4.6 世代以降の日付のないモデル ID は、1 つの固定されたモデルを指します。重みや設定は更新されず、更新版は新しい ID で出ます。ただし、各 ID には、それぞれの廃止の日程があります。古い記事の ID は、使えなくなっていることがあります（出典：Model IDs and versioning）。

選ぶ基準と、2 つの始め方

公式の「Choosing a model」は、最初に確かめる基準として、性能・速さ・費用・努力量（effort）を挙げています。effort は、同じモデルの中で、賢さと、速さ・費用のどちらを重くするかを調整するパラメータです（第 07 章）。公式は、「モデルを替えるより、effort の調整のほうが良い手段であることが多い」と書いています。

始め方は 2 つです。効率優先は、Haiku 5.5 から始めて、足りないときだけ上げます。性能優先は、Opus 5.5 から始めて、余裕があれば下げます。どちらを選んでも、決め手は自分の仕事での評価です。次の図で、決め方の流れを追ってください。

軽い作業は、軽いモデルで

文章の分類、短い下書き、項目の抜き出しのような、決まった形の大量の仕事は、軽いモデルで足りることがあります。難しい推論や、長い手順の仕事は、強いモデルが必要なことがあります。次の表は、この講座の見方です（公式の表ではありません）。

公式は、複数のモデルを組み合わせる方法も紹介しています。安いモデルと強いモデルを組み合わせ、多くのトークンを安い単価で処理します（出典：Choosing a model）。組み合わせ方の詳しい説明は、公式の Choosing a model のページから案内されています。この講座では扱いません。

つまずきやすい点

つまずきやすい点

1 つ目は、評価をせずに、評判や名前で決めることです。公式も、自分の仕事に合った評価の組を作ることを、選ぶ手順の中で最も大事な段階としています。2 つ目は、モデルの ID をコードに散らすことです。1 か所（設定）にまとめると、入れ替えが楽です。3 つ目は、モデルの入れ替えで、トークンの数え方が変わることです。世代によって、同じ文章でもトークン数が違うので、見積もりを取り直します（第 05 章）。
