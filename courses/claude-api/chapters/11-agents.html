エージェントとは

公式の Agent SDK の説明では、エージェントは、自分で手順を計画し、ファイルを読む、コマンドを動かす、コードを直す、といった道具を呼びながら、仕事を終わらせるアプリケーションです（出典：Agent SDK overview、2026 年 11 月 18 日確認）。仕組みは、第 09 章の繰り返しです。違いは、何回回すか、誰が止めるかにあります。

繰り返しは、止まる設計が先です

モデルが道具を呼び続けると、時間も費用もかかります。回数の上限、使ってよい量の上限、書き換えや送信の前の人の確認を、先に決めます（第 12・13 章）。

自分で書く：歯止めつきの繰り返し

次の例は、第 09 章のコードに、回数と使用量の上限と、読むだけの道具以外は人に確認する仕組みを足したものです。道具の定義は省いています。構文の検査だけをして、API を呼んで動かしてはいません。

import anthropic

client = anthropic.Anthropic()

SAFE_TOOLS = {"get_stock"}  # 確認なしで動かしてよい、読むだけの道具
MAX_STEPS = 8  # 繰り返しの上限
MAX_TOKENS_TOTAL = 20000  # 使ってよい出力トークンの合計の上限


def run_tool(name, args):
    if name == "get_stock":
        return "12"  # 架空の結果
    return "未対応の道具です"


def ask_human(name, args):
    answer = input(f"道具 {name} を {args} で実行してよいですか？ (y/n) ")
    return answer.strip().lower() == "y"


def run_agent(task, tools):
    messages = [{"role": "user", "content": task}]
    used = 0
    for _ in range(MAX_STEPS):
        response = client.messages.create(
            model="claude-haiku-5-5", max_tokens=1000, tools=tools, messages=messages
        )
        used += response.usage.output_tokens
        if response.stop_reason != "tool_use":
            return response  # 終わり
        if used > MAX_TOKENS_TOTAL:
            raise RuntimeError("使用量の上限に達したので、中断します")
        messages.append({"role": "assistant", "content": response.content})
        results = []
        for block in response.content:
            if block.type != "tool_use":
                continue
            if block.name in SAFE_TOOLS or ask_human(block.name, block.input):
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": run_tool(block.name, block.input)})
            else:
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": "利用者が実行を断りました", "is_error": True})
        messages.append({"role": "user", "content": results})
    raise RuntimeError("回数の上限に達したので、中断します")

どの方法で作るか

公式の Agent SDK のページには、作り方の違いを整理した表があります。次の表は、それをこの講座で言い直したものです。

MCP：外部の道具を、共通の決まりでつなぐ

MCP（Model Context Protocol）は、外部の道具やデータを、共通の決まりでつなぐ仕組みです。Messages API には、MCP コネクタがあり、公開された MCP サーバーを、自分で MCP の部品を書かずに、リクエストに載せられます。公式の説明では、ベータ機能で、専用のヘッダー（betas）が要ります。対応はツールの呼び出しだけで、サーバーは https で公開されている必要があり、手元の標準入出力のサーバーは直接つなげません。API が、あなたに代わって MCP サーバーを呼びます（出典：MCP connector）。

import anthropic

client = anthropic.Anthropic()

response = client.beta.messages.create(
    model="claude-haiku-5-5",
    max_tokens=1000,
    messages=[{"role": "user", "content": "使える道具を教えてください。"}],
    mcp_servers=[
        {
            "type": "url",
            "url": "https://example.com/mcp",  # 例。公開された https の MCP サーバーの URL
            "name": "example-mcp",
            "authorization_token": "YOUR_TOKEN",  # 必要なときだけ。実際の値はコードに書かない
        }
    ],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "example-mcp"}],
    betas=["mcp-client-2025-11-20"],
)
print(response.content)

書き換えや削除ができる道具は、許可する道具の一覧から外す（denylist）か、最初は全部を無効にして必要なものだけ有効にする（allowlist）のが、公式の勧めです。

つまずきやすい点

つまずきやすい点

1 つ目は、最初から強い権限を与えることです。読むだけの道具から始め、書く・送る・消す道具は、人の確認をはさみます。2 つ目は、上限がないことです。回数・使用量・時間の上限を、コードに書きます。3 つ目は、外部のサーバーを信用しすぎることです。接続先の道具が返す文章にも、指示のような文が混ざりえます（第 13 章）。4 つ目は、ベータ機能を、基盤にしてしまうことです。仕様が変わりうるので、公式の更新を確かめます。
