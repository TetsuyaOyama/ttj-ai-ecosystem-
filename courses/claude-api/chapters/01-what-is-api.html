前提：序章だけです。プログラミングの経験は要りません。

API とは、プログラムから使う入口

API（application programming interface）は、あるサービスの機能を、別のプログラムから使うための入口です。レストランに例えると、メニューと注文の決まりのようなものです。決まった形で注文を出せば、決まった形で料理が届きます。

Claude API は、Claude を自分のプログラムから使う入口です。公式ドキュメントは、Claude API を、https://api.anthropic.com にある REST 型の API と説明しています。文章を決まった形で送ると、Claude の答えが決まった形で返ります（出典：API overview、2026 年 11 月 18 日確認）。

決まった形のやり取りを、リクエスト（request、送る側）とレスポンス（response、返る側）と呼びます。形式は JSON（JavaScript Object Notation）という、項目と値を波かっこで囲む書き方です。第 03 章で、実物を 1 つずつ読みます。

図の部品を押すと、役割が出ます。あなたのプログラムが、API にリクエストを送り、API がモデル（Claude）に処理を頼み、結果がレスポンスとして返ります。API キーと支払いは、Claude Console（Anthropic の管理画面）で管理します。

チャットの画面との違い

チャットの画面では、人が文章を入力し、画面に答えが出ます。API では、プログラムが文章を送り、プログラムが答えを受け取ります。人が見ていなくても動かせるので、仕事の仕組みに組み込めます。

表で大事なのは、右の列の「自分のプログラムが受け持つ」ことです。会話の記憶、入力の準備、答えの確認、エラーへの対応は、自分の仕組みで決めます。画面では、これらが画面の機能として用意されています。

API で何ができるようになるか

文章を入れて、文章が返る仕組みなので、文章に関する仕事の多くが対象になります。たとえば、下書きの作成、要約、書類からの項目の抜き出し、分類、翻訳、コードの説明です。第 12 章で、7 つの利用例を、人の確認の位置まで含めて学びます。

公式ドキュメントの API の概要には、メッセージを送る Messages API のほかに、まとめて処理する Message Batches API、トークンを数える Token Counting API、モデルを一覧する Models API、ファイルを預ける Files API があります（出典：API overview）。この講座は、このうち、第 03 章から Messages API を中心に使い、第 05 章と第 10 章で、ほかの 3 つにも触れます。

この講座の範囲

Claude は、AWS・Google Cloud・Microsoft Azure のサービスからも使えます（出典：API overview）。この講座は、Anthropic が直接提供する Claude API だけを扱います。クラウド経由では、機能の提供の時期や料金の払い方が違うことがあります。

つまずきやすい点

つまずきやすい点

画面で Claude を使えている人でも、API は別の入口です。API には、Console でのキーの作成と、支払いの設定が要ります（第 02 章）。また、API は「前の会話を覚えている」前提で動きません。続きを話すには、これまでの会話を毎回送ります（第 04 章）。
