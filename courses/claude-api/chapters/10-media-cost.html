この章で分かること

  1. 画像と PDF を、リクエストのブロックとして渡す形を説明できる。
  2. プロンプトキャッシュとバッチ処理が、どんな費用の工夫か、使い分けを言える。
  3. キャッシュが効いたかどうかを、usage で確かめる方法を言える。

前提：第 05 章（トークンと料金）、第 08 章（資料の置き場所）。

画像と PDF を渡す

第 04 章で、user の content は「ブロックの一覧」にできると学びました。画像は image ブロック、PDF などの文書は document ブロックで渡します。渡し方は 3 通りで、base64 で本文に埋める、URL で指す、Files API で先にアップロードして file_id で指すです（出典：Vision、PDF support、2026 年 11 月 18 日確認）。公式は、画像や PDF を、文章より先に置くと、うまく働くとしています。

PDF は、各ページが画像に変換され、文字も取り出されて、両方がモデルに渡されます。そのため、図や表の読み取りもできます。そのぶん、ページが多いと入力トークンが増え、費用も増えます。サイズやページ数の上限は、変わりやすいので、公式の各ページで確かめてください（この講座には数字を書きません）。

画像の読み取りには、限界があります

公式は、小さい・回転した・画質の低い画像では精度が落ちること、数や座標の出力はおおよそであること、画像から人の名前を特定しないことを挙げています。重要な用途では、出力を必ず確かめます（第 12・13 章）。

費用と時間の工夫：2 つの道具

同じ長い資料を何度も渡す、件数が多い、といった場面には、2 つの工夫があります。単価の数字は第 05 章の表にあります。ここでは、仕組みと使い分けだけを学びます。

プロンプトキャッシュ：同じ前置きを再利用する

リクエストの先頭側（tools、system、messages の順）が、前回と1 文字も違わず同じなら、その部分を再利用して、読み取りの料金を安くできます。cache_control の印を付けた場所までが、再利用の対象です。公式の説明では、既定の保存時間は 5 分で、1 時間にもできます。短すぎる入力は、エラーにならず、単に使われません（最小の長さはモデルごとに違います）。効いたかどうかは、usage の cache_creation_input_tokens（書き込み）と cache_read_input_tokens（読み取り）で確かめます。両方が 0 なら、使われていません。

バッチ処理：急がない大量の仕事を、まとめて頼む

Message Batches API は、たくさんのリクエストを、まとめて非同期で処理します。公式の説明では、費用が安くなる代わりに、結果はすぐには返りません。ほとんどは 1 時間以内に終わりますが、保証ではなく、24 時間で打ち切られます。結果は順番どおりとは限らないので、各リクエストにつけた custom_id で突き合わせます。ストリーミングは使えません。

コードの例

1 つ目は、PDF を渡し、PDF のブロックにキャッシュの印を付ける例（同じ PDF に、質問を変えて何度も聞く場面を想定。印より前の system と PDF が再利用の対象で、短い system だけに印を付けても、最小の長さに届かず使われません）、2 つ目は、バッチを作って結果を読む例です。構文の検査だけをして、API を呼んで動かしてはいません。ファイル名と文面は架空です。

import base64
import anthropic

client = anthropic.Anthropic()

with open("report.pdf", "rb") as f:  # 手元の PDF（ファイル名は例）
    pdf_data = base64.standard_b64encode(f.read()).decode("utf-8")

response = client.messages.create(
    model="claude-haiku-5-5",
    max_tokens=1000,
    system="あなたは、資料の内容だけを根拠に答える担当者です。",
    messages=[
        {
            "role": "user",
            "content": [
                {  # 資料を先に、質問を後に置く
                    "type": "document",
                    "source": {"type": "base64", "media_type": "application/pdf", "data": pdf_data},
                    "cache_control": {"type": "ephemeral"},  # ここまで（system と PDF）を再利用する印
                },
                {"type": "text", "text": "この資料の要点を、3 つの箇条書きでまとめてください。"},
            ],
        }
    ],
)

print("".join(b.text for b in response.content if b.type == "text"))
print(response.usage)  # cache_creation_input_tokens と cache_read_input_tokens も、ここで確かめる

import anthropic
from anthropic.types.message_create_params import MessageCreateParamsNonStreaming
from anthropic.types.messages.batch_create_params import Request

client = anthropic.Anthropic()

texts = {"item-001": "（架空の文面 1）", "item-002": "（架空の文面 2）"}

batch = client.messages.batches.create(
    requests=[
        Request(
            custom_id=cid,
            params=MessageCreateParamsNonStreaming(
                model="claude-haiku-5-5",
                max_tokens=300,
                messages=[{"role": "user", "content": "次の文面を、1 文に要約してください。\n" + body}],
            ),
        )
        for cid, body in texts.items()
    ]
)
print(batch.id, batch.processing_status)

# しばらくしてから、processing_status が "ended" になったことを確かめて、結果を読む
for item in client.messages.batches.results(batch.id):
    if item.result.type == "succeeded":
        text = "".join(b.text for b in item.result.message.content if b.type == "text")
        print(item.custom_id, text)
    else:
        print(item.custom_id, item.result.type)  # errored・canceled・expired

つまずきやすい点

つまずきやすい点

1 つ目は、前置きに、毎回変わる値（時刻など）を入れることです。1 文字でも違うと、キャッシュは使われません。2 つ目は、道具の定義や system を途中で変えることです。変えた場所以降の再利用が無効になります。3 つ目は、バッチの結果を、順番どおりだと思うことです。custom_id で突き合わせます。4 つ目は、バッチの結果に保存期限があることです。早めに取り出して、自分の側に保存します。5 つ目は、急ぐ仕事にバッチを使うことです。時間の保証がありません。
