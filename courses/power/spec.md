### 0.1 内容の決まり（全章共通・変えない）

1. **公開情報だけ**を使う：各国の当局とエネルギー機関の統計・白書（資源エネルギー庁、経済産業省、環境省、米国エネルギー情報局〔EIA〕、IEA など）、電力広域的運営推進機関（OCCTO）・一般送配電事業者・海外の系統運用者の公開資料、学協会（日本ガスタービン学会、日本機械学会、火力原子力発電技術協会、電気学会、ASME、IEEE など）の公開資料、規格団体（ISO、IEC、JIS〔日本産業標準調査会〕、ASME の試験規格など）の公開ページ、メーカー・事業者の公式資料（製品ページ・技術論文・報道発表・決算説明資料・発電所のページ）、e-Gov などの法令の公式の条文、教科書的な一般知識。報道・まとめ・個人のブログ・動画・有料の調査報告の非公開部分を根拠にしない。
2. **企業名・機種名は公開情報の範囲で実名可**。ただし**優劣の評価をしない**（「◯◯社の機種が優れる」「世界最高の」と書かない。メーカーが自社の公表で使う「世界最高効率」などの言葉は、「◯◯社は〜と発表している」と主体を示して引くだけにし、本文の地の文にしない）。機種・発電所の例を表に載せるときは、比較・順位を付けず、「例であり、優劣や推奨を示さない」と表の注記に書く。演習・ケースの人物・会社・発電所は**必ず架空**（「発電事業者 A 社」「メーカー B 社」「発電所 C」）。
3. **数字（出力、熱効率、タービン入口温度、圧力比、排出量、市場規模、納期、燃料の量）には、必ず出典と時点と条件を付ける**。条件は §8.13 の書式（発熱量の基準、発電端か送電端か、単純サイクルか複合サイクルか、大気条件、負荷、保証値か実績か）。確認できない数字・条件の分からない数字は書かない（「目安」「一般に」で埋めない）。変わりやすい数字を確認問題・総合テストの正答にしない。
4. **費用と価格は仕組みだけ**：発電の費用・燃料の価格・電力の市場価格・機器の価格の**実際の金額は載せない**。費用の構造・計算の仕方は、「架空」と明記した値で示す。価格・需要・受注・納期の**予想はしない**（主体が公表した予測は、主体・シナリオ名・公表日を付けて「予測」と書く）。
5. **投資の推奨、銘柄の評価をしない**。企業の業績・株価・銘柄コードに触れない（事業の区分の名前と、事業の仕組みの説明に使う公表値だけ）。該当する章に §9.3「投資」を置く。
6. **安全に関わる内容**（高電圧、高温・高圧の蒸気と水、可燃性のガス〔天然ガス・水素〕、回転機械、アンモニアなどの化学物質、重量物、保守の作業）は、**仕組みと注意点の説明にとどめ、手順書・設計・判定の基準の代わりにしない**。該当する章に §9.3 の定型の注意書きを置く。次は**書かない**：運転の操作の手順と設定値、保護の設定値、燃焼の調整の値、点検・補修・溶接の手順と合否の基準、強度・肉厚などの設計の計算、高圧ガス・水素・アンモニアの取扱いの手順、遮断器・開閉器の操作の手順。存在と危険と「誰が何に従って行うか」を言葉で示すだけにする。
7. **輸出管理**は制度の仕組みの説明にとどめ、個別の製品・技術の該非・許可の要否を判断しない（§9.3「輸出管理」）。
8. **法令と制度は、どの国・地域の話かと、確認の時点を明示する**（§8.14）。個別の案件の許認可の要否・手続き・規制への適合を判断しない（§9.3「法令と制度」）。

## 1. 講座の狙い・読者・到達点

**狙い**：電気が「誰の、どの設備で作られ、どう系統で需要と釣り合わされ、どんな市場で売られるか」という発電事業の仕組みを土台に、コンバインドサイクル発電（ガスタービンと蒸気タービンの複合発電）の熱力学の原理、ガスタービンと発電所の機器、起動・運転・保守、建設と試運転、産業の構造と脱炭素の技術までを一続きで説明できるようにする。結論を覚えるのではなく、**数字をどの条件で読み、どの資料のどこで確かめるか**を身につける。

**読者**：理工系の基礎（高校から大学初年の物理・化学・数学）はあるが、発電や電力事業は初めての社会人。電力会社・発電事業者・重電メーカー・プラント建設・商社・金融・コンサルティングで、発電の案件に関わり始めた人。数式は四則演算・べき乗・比（§9.4 の式だけ。微分積分は使わない）。

**読み終えた後にできること**

1. 電力系統（発電・送電・配電・小売）の設備と事業者の役割、需要と供給を一致させる仕組みと周波数、電源ごとの役割（ベース・ミドル・ピーク、調整力）を、日本の制度の名前で説明できる。
2. 発電事業者が何を売るか（kWh・kW・ΔkW・非化石価値）と市場の種類、発電の費用の構造（固定費・可変費・燃料費・メリットオーダー）、LNG の供給網を説明できる。
3. ブレイトンサイクル・ランキンサイクル・複合サイクルの熱効率を、状態点の表と §9.4 の式で計算でき、公表された熱効率を「低位発熱量か高位発熱量か、発電端か送電端か、単体か複合か、どの大気条件か」に切り分けて読める。
4. ガスタービンの圧縮機・燃焼器（低 NOx 燃焼）・タービン（翼の冷却・耐熱材料・遮熱コーティング）・軸受と補機・吸気と排気の役割と、出力と効率が大気条件で変わる理由、機種の形式と世代の公表の読み方を説明できる。
5. 排熱回収ボイラ・蒸気タービン・復水器と冷却・発電機と変圧器と系統連系・制御と保護の構成、起動・停止・負荷追従の流れ、運転の指標、点検の周期の考え方と高温部品の検査・補修、建設と試運転の段階を、実務者の言葉で説明できる。
6. 重電メーカーと保守事業・供給網と納期の公表の読み方、環境規制と許認可の枠組み（国と確認日つき）、水素・アンモニアの混焼と CO2 回収の技術課題、再生可能エネルギーの拡大と需要の動向の中でのガス火力の役割を説明でき、案件の各段階で確かめる事実と相談先を選べる。

## 3. 全章の一覧

凡例：**項目**＝扱う項目（①〜）。**部品**＝使う部品・データ id・題材（データ形式は FRAMEWORK §4）。**問**＝確認問題 3 問の題材。**演**＝演習。計算の演習は、式（§9.4 の番号）・架空の値・答えと、データに貼る**検算の行**（§8.6。自己点検が計算し直す）を設計の段階で決めてある。値を変えるときは検算の行も直し、自己点検で `OK` を確かめる。**Web**＝執筆時に Web で確認する事実（一次資料の個別ページで。§8.2。★は公開直前に再確認）。**資料**＝主な参照資料の種類。**持ち主**＝その章だけが数字・定義・図を書く事実（§9.1）。**注意書き**＝§9.3 の定型文の名前（`--warn` に渡す名前と同じ）。

#### 02 需要と供給の一致と周波数
- ねらい：電気はためにくく、需要と供給を時々刻々一致させる必要があることと、ずれると周波数が変わる仕組み、周波数を戻す制御の段階と、大きな電源が止まったときに起きることを説明できる。
- 項目：①同時同量と需要の形（1 日と季節の需要の変化。値は OCCTO・一般送配電事業者の公開実績、年度と日付） ②周波数と回転機の関係（同期発電機の回転と系統の周波数。式 20） ③需給のずれと周波数の変化（慣性、周波数の変化の大きさを決めるもの。式 21 は講座の簡略化） ④周波数を戻す制御の段階（慣性による応答、ガバナフリー、負荷周波数制御〔LFC〕、経済負荷配分。名前は OCCTO・一般送配電事業者の資料の語） ⑤周波数の目標の範囲（一般送配電事業者の公表値と出典） ⑥電源の脱落と負荷の遮断（周波数の低下で負荷を切り離す仕組み〔UFR〕、2018 年 9 月の北海道の全域停電の公的な検証の要点） ⑦東西の周波数変換設備と地域間連系線（容量と増強の計画は出典と時点つき）
- 部品：`state` **c02-freq**（系統の周波数の状態：通常 → 電源の脱落 → 周波数の低下 → 一次の応答 → 二次の制御 → 回復。分岐：低下が続く → 負荷の遮断 → 回復、または全域停電）、`seq` **c02-seq**（大きな電源が止まった 1 回：登場者は「発電所 A（脱落）」「系統（周波数）」「他の発電所（ガバナ）」「中央給電指令所」「需要家の設備〔負荷の遮断の装置〕」。各手の時間は出典があるときだけ書き、なければ時間の言葉も書かない）、`table` **c02-ctrl**（周波数の制御の段階の早見表：名前〔出典の語〕・働き始める時間の区分〔出典の言葉〕・担う設備・関係する市場の商品〔第04章へのリンク〕・出典）、`ident` **c02-speed**（回転数の式の解剖：`120 × 周波数 ÷ 極数`。「2 極・50 Hz → 3,000 rpm」の例）
- 問：電気をためにくいことから同時同量が必要になる理由／ガバナフリーと負荷周波数制御の違い／周波数が大きく下がったときに負荷を切り離す目的 ｜ 演（計算。式 20・21、値は架空）：①2 極の発電機の回転数は 50 Hz で 3,000 rpm、60 Hz で 3,600 rpm、4 極・50 Hz で 1,500 rpm。②系統の周波数特性を K ＝ 1,000 MW/Hz（架空の簡略化した定数）とし、500 MW の電源が脱落したときの一次の周波数の低下は 0.5 Hz（一次の応答だけを見る簡略化と明記）
  - 検算の行：`検算 回転数50Hz: 3000 = 120 * 50 / 2`、`検算 回転数60Hz: 3600 = 120 * 60 / 2`、`検算 回転数4極: 1500 = 120 * 50 / 4`、`検算 周波数の低下: 0.5 = 500 / 1000`
- Web：OCCTO の調整力の区分と用語（業務規程・送配電等業務指針・用語の解説）、周波数の目標の範囲（一般送配電事業者 2 社の公表、時点）、北海道の全域停電の検証（OCCTO の検証委員会の最終報告、公表日）、UFR の仕組みの公的な説明、★周波数変換設備の容量と増強の計画（OCCTO の広域系統長期方針・計画、時点）、系統の周波数特性の定義（教科書か OCCTO の資料。定義が %MW/Hz の形なら、式 21 との関係を A に知らせる）
- 資料：OCCTO、一般送配電事業者、電力工学の教科書
- 持ち主：周波数の制御の段階、回転数と周波数の式（式 20）、周波数変換設備と連系線の容量、北海道の全域停電の検証の要点

## 6. 部品

### 6.1 新しい部品：なし

基盤の 17 種（`arch` `seq` `flow` `layers` `xsec` `route` `stack` `ident` `table` `tree` `state` `drill` `quiz` `compare` `mapping` `glossary` `exam`）だけで作る。検討した候補と結論：

- **温度とエントロピーの線図・温度と熱量の線図（連続のグラフ）**→ 足さない。**状態点の表（`table`）と、状態点を座標に置いた模式図（`arch`）の対**で表す。描き方の決まりは §6.5。自己点検（§8.10 の 15）が、表の温度と順の並びと、図の点の上下左右の並びが一致するかを機械的に確かめる。
- **性能の補正の線（外気の温度と出力）・圧縮機の性能の線図**→ 足さない。**架空の値の表**（`c16-ambient`、`c12-map`）で、表を読む練習にする。実在の機種の補正の線は描かない（値の出典が要り、機種の比較に近づくため）。
- **熱効率・燃料費・混焼の計算器**→ 足さない。式は `ident`（`c06-eff`、`c04-fuelcost`、`c29-blend` など）、計算は架空の値の演習と確認問題で扱う（第2弾・第3弾と同じ判断）。
- **負荷曲線・需要の推移のグラフ**→ 足さない。架空の値の表（`c03-resid`）と、出典の値の早見表（`c03-mix`、`c30-outlook`）で扱う。
- **機器の断面**→ `layers`（ガスタービン・燃焼器・動翼・排熱回収ボイラ・蒸気タービン）と `xsec`（遮熱コーティング）で足りる。`xsec` の材料の色は固定で、`materials` で名前を言い換える（第2弾の第16章、第3弾の第08章と同じ使い方）。
- **契約で変わる負担者**→ `route` で足りる。`mode` は輸送用の記号だが、発電所の中の区間は `site`、輸送は `land`・`sea`、通関は `customs`、保管は `store` と決め、図の注記で「設備の区間」と書く。

### 6.5 線図（温度とエントロピー・温度と熱量）の描き方

基盤に連続のグラフの部品は無いので、線図は**状態点の表と、状態点をつないだ模式図の対**で表す。第07章が見本の章（C が最初に書き、他の担当は第07章のデータを写して使う）。

1. **対の id**：表は `cNN-pts`、図は `cNN-ts`（温度と比エントロピー）か `cNN-tq`（温度と熱量）。1 章に 2 対以上置くときは `cNN-pts-名前` と `cNN-ts-名前` のように、`-ts`・`-tq` を `-pts` に置き換えると対の表の id になる形にする（自己点検はこの置き換えで対を探す）。
2. **表の列**（この名前で。順もこのまま）：`点`／`場所`／`圧力（MPa、絶対圧）`／`温度（℃）`／`温度（K）`／`s の順`（温度と熱量の図は `Q の順`）／`比エンタルピー（kJ/kg）`（使う章だけ）／`出典`。2 つの作動流体を重ねる図（第09章）だけ、`流体` の列を足す。`温度（K）` は `温度（℃）` ＋ 273.15 を整数に丸めた値（式 7。丸めたことを表の `note` に書く）。値は「架空」（列「出典」に「架空」）か、出典の値。蒸気表の値を使うときは蒸気表の名前と版を出典に書く。
3. **順の列**：`s の順` は比エントロピーの小さい方からの順位（1 から。同じ値は同じ順位）。実際の比エントロピーの値は書かない（架空のサイクルで細かい値を作らないため）。`Q の順` は、低温の端から数えた受け渡した熱量の順位。
4. **図の点**：`arch` の `nodes` に、表の行ごとに 1 つ。`id` は `p` ＋ 点の名前（点「2a」→ `p2a`、点「g1」→ `pg1`）。`label` は点の名前、`sub` は場所の短い名前。**すべて同じ `w`・`h`**（例：w 44・h 28）。
4a. **温度の整合（複合サイクルなど、2 つの流体を重ねる表）**：蒸気側の最高の温度（主蒸気）は、熱を渡すガスタービンの排気の温度より低くする（熱は高温から低温へ流れる）。第09章は主蒸気 573 K（300 ℃）＜ 排気 637 K、煙突の点 5（373 K）＞ 給水（307 K）で、矛盾しない。
5. **置き方**：横は順の列の順に左から右（同じ順位は同じ `x`）、縦は温度の高い点ほど上（`y` が小さい。同じ温度は同じ `y`）。**順序だけを表し、間隔には意味がない**。目盛りの数字・軸の値を図に書かない。点が重なるときは、表の値を架空の範囲で少しずらす（第08章の点 2 のように）。
6. **線**：作動流体がたどる過程は `up`（`label` は「圧縮」「加熱」「膨張」「放熱」など、`carries` は作動流体の名前）。比べるために重ねる理想の過程は**別の `id`** の線で `lg`。**`cp` は使わない**。線は直線で結んだ模式で、実際の等圧線などは曲線であることを `hint` に書く。
7. **`hint` の定型文**（そのまま使う）：温度とエントロピーの図は「横は比エントロピー（右ほど大きい）、縦は温度（上ほど高い）の順だけを表す模式図です。目盛りはなく、点の間隔に意味はありません。線は点を直線で結んだもので、実際の過程の線は曲線です。値は下の表を見てください。」。温度と熱量の図は「横は受け渡した熱量（右ほど多い）、縦は温度（上ほど高い）の順だけを表す模式図です。目盛りはなく、点の間隔に意味はありません。値は下の表を見てください。」
8. **重ねる図**（第09章）：`views` で「ガスタービン側」「蒸気側」「重ねた模式」に分け、重ねた表示の `hint` の定型文の後に「空気と水・蒸気の比エントロピーは同じ目盛りでは比べられません。2 つのサイクルを重ねた模式です。」を足す。表の `流体` の列がある図では、自己点検は同じ流体の点どうしだけを比べる。
9. **飽和の線**（第08章）：飽和の線（山の形）は描かない。飽和水と飽和蒸気の点を状態点として置き、`desc` に「この 2 点の間で、温度が一定のまま水が蒸気に変わる」と書く。`groups` の枠で湿り蒸気の範囲を描かない（形が実際と違うため）。
10. **置き場所**：本文では、表を先に、図をその直後に置く。図の上の段落で、表のどの列を見るかを 1 文で書く。
11. **幅**：`viewBox` の幅は 700 以下（狭い画面で横に動かさずに読める）。

### 8.1 事実確認表（全章必須）

**置き場所**：章のデータファイル `data/NN-*.js` の先頭のコメント。30 行を超えるときは `facts/NN-同じ名前.md` に置き、データファイルの先頭に「事実確認表：facts/NN-….md」と 1 行書く。読者向けの本文には出さない。

**書式**（列はこの順。空欄にしない。該当しない欄は「—」）：

```
/* 第NN章 事実確認表（担当 X、確認 YYYY-MM-DD〜YYYY-MM-DD）
| # | 区分 | 事実（本文での書き方） | 数値・単位 | 時点・版 | 出典（発行者『資料名』） | URL（個別ページ） | 一次 | 確認日 | 使った箇所 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 制度 | 【日本】（架空の例）法 X の施行規則の別表は、施設 Y の基準を定めている | ◯◯ ppm | 最終改正 2025-04-01 施行 | e-Gov『法 X 施行規則』 | https://laws.e-gov.go.jp/law/… | ○ | 2026-11-20 | 本文 §2、c28-laws の 3 行目 |
| 2 | 仕様値 | （架空の例）機種 Z の複合サイクルの熱効率（メーカーの呼称「発電効率」）。条件：低位発熱量基準・発電端・1 on 1・ISO 条件・保証値かどうかの記載なし | ◯◯% | 製品ページ（確認 2026-11） | B 社『Z の製品ページ』 | https://…/z | ○ | 2026-11-20 | c17-models |
| 3 | 企業 | （架空の例）C 社の本社は ◯◯。社名変更：あり（YYYY-MM-DD に旧社 D から分離して現社名。会社概要の沿革で確認） | — | 会社概要（確認 2026-11） | C 社『会社概要』 | https://…/about | ○ | 2026-11-20 | 本文 §1、c27-makers |
確認できず書かなかった：
- （項目と、探した資料）

```

- **区分**（必ずどれか 1 つ）：`発表`（年月日・主体・共同の相手）／`企業`（社名の表記・本社の国・地域・社名の変遷）／`制度`（法令・制度の名称・公布・施行・改正・所管・規模の数値）／`規格`（名称・番号・**版・公表日**・発行者）／`仕様値`（機種・発電所の公開値と、**その値の名前と条件**）／`市場`（市場規模・受注・納期・輸入量・需要の想定などの統計と調査の値と、その**定義と条件**）／`安全`（安全の注意・禁止の根拠）／`保証`（保証・契約の扱い）／`定義`（用語・式）／`一般知識`（教科書的な内容。数値を伴うなら出典の教科書名を書く）。
- **一次**：`○` 発表の主体・規格団体・メーカー・当局自身の個別ページ／`△` 主体の原文を配信サービスが掲載したもの／`×` 報道・解説・まとめ。
- **高リスクの区分**（`発表` `企業` `制度` `規格` `市場` `安全` `保証`）は `○` か `△` だけで書く（第3弾の区分に `市場` を足した）。`×` しか見つからないものは**書かない**。`仕様値` も原則 `○`。
- **区分ごとの必須の書き方**（自己点検 12 が機械的に確かめる）：
  - `制度` の行の「事実」は**【国・地域】で始める**（【日本】【EU】【米国】【英国】など。§8.14）。
  - `企業` の行の「事実」に**「社名変更：なし」か「社名変更：あり（変更の日と旧社名、確かめた資料）」**を書く（§8.12）。
  - `仕様値` と `市場` の行の「事実」に**「条件：」**を書き、§8.13 の条件（効率なら発熱量の基準・端・範囲、出力なら範囲と大気条件、市場なら定義と単位と期間）を写す。出典に条件が書かれていないときは「条件：発熱量の基準の記載なし」のように**無いことを書く**。
  - 確認日は `YYYY-MM-DD`。
- 確認問題・総合テスト・図のデータの中の事実も表に載せる（`使った箇所` にデータ id）。
- 下書きでは、確認前の事実を本文に入れない。どうしても置くときは `【要確認】` の印を付け、表の行を作ってから外す。**ビルドの前に `grep -rn '要確認' chapters data facts` が 0 件**であること。

### 8.2 高リスクの事実の確認の仕方

第3弾の 1〜13 を引き継ぎ、14〜20 を足します。

1. **年月日**：原文の発信日・公布日・施行日・公表日を `YYYY-MM-DD` で写す。記憶・二次情報・検索結果の要約の日付を使わない。
2. **発表の主体**：原文の発信者と、共同発表の相手を原文で確かめる。
3. **企業の国**：各社の公式サイトの会社概要か IR の本社所在地で確かめる。日本法人の所在地と本社の国を混同しない。
4. **制度の規模**：名称・施行日・規模を、当局の個別ページ・条文の文言どおりに写す。「以上」「超」「未満」「以下」を言い換えない。
5. **主張の帰属**：根拠の資料が 1 つなら、主体は 1 つだけ書く。
6. **用語**：企業・団体の資料を引くときは、その資料の表記を使う（各社の呼称を一般名に、一般名を各社の呼称に言い換えない。資料が使っていない技術名を当てはめない）。
7. **一般化と条件**：1 つの資料・1 つの機種・1 つの国の事実を「一般に」「どの発電所でも」に広げない。原文に付いた条件（「屋外の」「新設の」「一定の規模以上の」）を落とさない。
8. **現在性**：製品の提供状況・社名・団体の名前・所管は変わる。社名と団体の名前の変更（§8.12）を確かめる。
9. **数値の換算**：単位換算・合計・比率を自分で計算した値を事実として書かない（出典の値をそのまま書く）。計算は架空の値の演習でだけ行う。**発熱量の基準の換算（式 15）も、実在の発電所の値には使わない**（基準ごとの値は出典の値だけ）。
10. **規格の版**：発行団体の公式の仕様のページ・販売のページで、現行の版と公表日を確かめる。本文は「執筆時点（YYYY 年 M 月）で確認できた最新の版は ◯◯（YYYY 年 M 月公表）」と書く。確かめられないときは版を書かず、規格の名前だけにする。★の項目は、公開の直前に検証担当がもう一度開く。
11. **安全の記述**：安全の注意・禁止は、メーカーの公開資料、当局・学協会の公開資料から書く。当局の資料は**最新の公表日の資料**を探してから使う。
12. **機種・発電所の仕様値**：値と一緒に**値の名前**（「発電効率」「熱効率」「タービン入口温度」「燃焼温度」など、出典の呼称のまま）と、§8.13 の条件を写す。名前や条件の違う値を同じ列に並べるときは、列の見出しを「公表値（名前と条件は行ごと）」にし、名前と条件を値の前に書く。
13. **保証・契約の扱い**：保証値・長期保守契約などは、公表された文言どおりに写し、1 社・1 件の例を全体に広げない。
14. **法令の現行**：法令は e-Gov など公式の条文で、現行の条文と最終改正・施行の日を確かめる（§8.14）。当局の解説だけで条文を確かめていないときは、そのことを事実確認表に書く。
15. **規模の単位を変えない**：法令・制度の規模の数値は原文の単位で書く（「万 kW」を MW に、「kW」を MW に直さない）。本文で補うときは「（原文の単位のまま）」と書く。
16. **時期の語を変えない**：「公布」「施行」「策定」「決定」「開始」「初回の入札」「約定」「運転開始」「営業運転の開始」「商用運転」「実証の開始」を原文の語のまま書く。発表の日と、出来事の日を区別する。
17. **予測と実績**：需要の想定・見通し・市場の予測は、**主体・資料名・シナリオ名・公表日**を付けて「予測」「想定」と書く。実績と同じ表の列に混ぜない。
18. **メーカーの公表値**：「◯◯% 以上」「◯◯ ℃級」「世界最高」などの表現は、主体を示して原文の言葉のまま引く（言い換えない。地の文にしない。§0.1-2）。
19. **公表のしかたの変更**：受注・受注残・納期・需要の想定などは、**最新の公表で同じ形の公表が続いているか**を確かめる。終わった・変わったときは、そのことと時点を書く。
20. **審議中・係争中**：法案・規則案・訴訟の対象になっている制度は、確かめた段階（提出・委員会・議決・公布・差し止めなど）と確認日を書き、成立や効力を推測しない。

### 8.3 参照リンク

- 参照資料の表のリンクは、**その事実が載っている個別ページ**（条文のページ、PDF、製品ページ、発表、統計の表）にする。公式サイトのトップ・製品一覧・ニュース一覧にしない（自己点検 5）。
- 個別ページの URL を一次資料で確かめられないときは、その事実を書かない。
- 有料の規格（ISO、IEC、ASME など）は、発行団体の公開ページ（概要・販売ページ）にリンクし、表の「この章での使い方」に「規格本文は読んでいない」かどうかを書く。
- 他章で確認済みの事実を使うときは、その章へのリンク（`#chNN`）にし、自分で数字を書き写さない（§9.1）。
- 参照資料の種類（付録の `c32-refs` の `filter` と揃える）は次の 6 区分だけ：**規格・仕様**／**団体の資料**（学協会・業界団体・国際機関の資料）／**企業の資料**（メーカー・発電事業者・燃料の供給者の製品ページ・技術論文・発表・決算資料）／**当局・公的機関**（官庁・規制機関・OCCTO・系統運用者・e-Gov・官報）／**教科書・一般知識・他講座**／**架空（見本のため）**。迷ったら発行者で決める（第2弾の REVIEW-part5 M4）。IEA は国際機関なので「団体の資料」ではなく「当局・公的機関」に入れる（第2弾の検証の判断と同じ）。

### 8.4 章の間の食い違いを防ぐ

- §9.1 の「事実の持ち主」の章だけが数字・定義を書く。持ち主でない章は、言葉で触れて持ち主の章へリンクする。特に、**機種を並べた比較表は第17章の `c17-models`、熱効率の公表例の表は第09章の `c09-claims`、法令の規制値の表は第28章の `c28-laws`** だけに置く。機種の数字は、各章が「出典・時点・条件つきの例」として書いてよい（値の名前と条件〔§8.13〕を付け、第17章の表と食い違わせない。機種どうしを並べて比べない）。
- 持ち主の章の担当は、確定した事実確認表を早めに共有し、他の担当はそれを読んでから書く（§7.3）。
- 用語の割り当ては `GLOSSARY-RULES.md` §8。図のラベル・本文・用語集の表記を一致させる。
- 本文の説明に出てくる機器・段階は、同じ章の図に描かれているか、描かれた図へのリンクがあるかを確かめる（第2弾の REVIEW-part3 M4：図に無い機器を説明に書いた）。
- 計算サーバー講義・自作PC講義と同じ語は、同じ表記・食い違わない説明にする（`GLOSSARY-RULES.md` §10）。相互参照は §3 の 3 か所だけ。

### 8.5 確認問題・総合テスト・演習

**数と形**

- 確認問題は**各章ちょうど 3 問**、選択肢は**各問 4 個**。総合テストは §3 の数（1 問か 2 問）。
- **正答の添字（`a`）は次の式で決める**（第2弾・第3弾と同じ式）：第 NN 章の k 問目（k＝1〜3）は `a = (NN + k − 1) mod 4`。例：第01章は 1・2・3、第02章は 2・3・0、第04章は 0・1・2。総合テストは `a = (NN + 2) mod 4`（2 問の章の 2 問目は `(NN + 3) mod 4`）、第32章の横断の 2 問は 0・1。

**書き方（正答の添字の誤りを防ぐ）**

1. 問ごとに、まず式で `a` を決める。
2. **正答の文を、配列の `a` 番目に最初に書く**。そのあと残りの位置に誤答を埋める（正答を 0 番に書いてから並べ替えない）。
3. `why` の最初の文に、正答の文の要点を書く（例：「正答は『低位発熱量基準と高位発熱量基準で…』です。」）。
4. 正答が 1 つだけかを確かめる：誤答が別の読み方で正解にならないか（条件の書き忘れ、「〜だけ」「必ず」の有無、発熱量の基準の書き忘れ）を、問題ごとに 1 回読み直す。
5. 位置に依存する選択肢（「上のすべて」「A と B」）、否定形の問い、変わりやすい数字（機種の出力・熱効率・市場の数字・制度の数値）を正答にする問題は作らない。計算の問題は、架空の値と §9.4 の式だけで作る。
6. 解説（`why`）は正答の理由と、もっとも選ばれやすい誤答がなぜ違うかを書く。解説が本文の原則（例：条件のそろわない数字を比べない、手順は現場の手順と製造者の指示に従う、法令は国と時点で確かめる）と矛盾しないかを読み直す。

**演習（`drill`・並べ替え・計算・分類）**

- 並べ替えの演習は、**提示の順を答えの順と変える**（答えが提示順と同じなら出題し直す）。
- `drill` の正答（止まった段階・最初に確かめる対象・最初に動く担当）は、**同じ講座の他の図と食い違わないか**を、ケースごとに照らす（第24章は `c24-seq`・`c24-tree`・`c23-protect`、第31章は `c31-seq`・`c22-connect`・`c28-eia`・`c26-flow`・`c26-phases`）。食い違ったら図の持ち主の章に合わせる。`procedure` の名前は `seq` の段階の名前と、`nodes` の名前は `tree` の葉・`seq` の登場者の名前と一字一句同じにする。
- 計算の演習は §8.6 の手順で検算する。

**演習の照合（全章必須。付録を除く）**：データファイルの事実確認表の下に、次の表を置く。確認問題 3 問・総合テスト・演習のすべての正答について、**解説と本文・図が同じことを言っているか**を 1 行ずつ書く（第2弾・第1弾の M1・M7 は、正答と他の図の主体が食い違っていた）。

```
演習の照合（第NN章）
| 問・演習 | 正答（要点） | 照らした本文・図（節・データ id・手の番号） | 本文・図の記述（要点を写す） | 一致 |
|---|---|---|---|---|
| c24-quiz 問2 | 最低の負荷が排出の制約で決まることがある | 本文「負荷追従」の 2 段落目 | 「…排出の制約で…」 | ○ |
| c24-drill ケース 3 | 段階「並列」、対象「同期の装置の記録」 | c24-seq 手 7（phase「並列」）、c24-tree の葉「同期の装置の記録」 | （写す） | ○ |
```

**機械での検証**：§8.10 の自己点検（3・14）を、章を書き終えるたびに走らせる。式どおりでない・選択肢が 4 個でない・`why` が無い問題、「演習の照合」の表が無い章は `NG` になる。`NG` が 0 件でも、出力された `問`・`正答`・`解説` の組と、演習の `段階`・`対象` の組を全部目で読む（式では「その位置の文が正しいか」は検査できないため）。

### 8.6 定義と式の照合と、計算演習の検算（§3 に検算の行がある章すべて：02〜10・12〜14・16・18〜22・24・25・28〜30。自己点検は `--calc` を付けて走らせる）

- 式は §9.4 が正。章で式を書くときは §9.4 の形・記号・単位・分子と分母の向きを変えない。本文の式は §9.4 の「言葉の式」で書き、記号の式は `ident` の中と補足だけにする。
- データファイルの事実確認表の下に、次の 2 つを置く。

```
定義と式の照合（第NN章）
| 量 | 本文の定義の文 | 式（§9.4 の番号） | 用語集の d | 演習・問の使い方 | 一致 |
|---|---|---|---|---|---|
| 熱効率 | 電気出力を、燃料の入熱で割った割合。発熱量の基準と端を必ず書く | 式 3 | （同じ文） | 演習 1：300 ÷ 500 ＝ 60%（低位発熱量基準・発電端、架空） | ○ |

検算 発電端効率: 60 = 300 / 500 * 100
検算 ヒートレート: 6000 = 3600 / 0.60
```

**計算演習の検算の手順**

1. **設計の値をそのまま使う**：§3 の各章の「検算の行」を、データファイルのコメントにそのまま貼る。値を変えるときは、本文・確認問題・解説・用語集・図の注記のすべての数字と、検算の行を一緒に直す。
2. **検算の行の形**：`検算 名前: 答え = 式`（1 行に 1 つ、行の終わりにコメントの閉じ `*/` を置かない）。式に使えるのは数字・`+ - * / ( )`・べき乗の `**` だけ。答えは本文に書く値（丸めた値）。単位は式に書かず、「名前」に単位を入れる（例：`検算 排熱kW: 330000 = …`）。
3. **2 回計算する**：1 回目は担当が手で（または別の電卓で）計算して検算の行を書く。2 回目は自己点検（§8.10 の 13）が式を計算し直し、答えとの差が 0.5% を超えたら `NG` にする。
4. **単位の換算は 1 か所で**：kW で計算して本文で MW と書くときは、本文に「330,000 kW（330 MW）」のように両方を一度書き、検算の名前に単位を入れる。kJ/s ＝ kW、MJ/s ＝ MW の関係は §9.4 の式 2 の注のとおり。
5. **前提を書く**：比熱を一定とする、理想の過程とする、一次の応答だけを見る、メタンだけが CO2 を出す、などの簡略化は、演習の文と解説の両方に書く。「架空」の値は「架空」と書く。
6. **照合表で 4 か所をそろえる**：定義の文・式・用語集の説明・演習の答えの 4 つが同じことを言っているかを、照合表の 1 行ずつで確かめる（第2弾の REVIEW-part1-2 M1 は、定義の文と式が別の定義を前提にしていた）。
7. 用語集の `d` に式・数値を入れない（`GLOSSARY-RULES.md` §7）。
8. 「約」「ほぼ」を付けた定義は、出典の言い方どおりにし、演習では「（架空の前提）」と前提を明記する。

### 8.7 図の線の種別（`plane`）と色の種別（`kind`）

1. **線の種別は、その線が運ぶものだけで決める**（§6.2）：物とエネルギーは `up`、信号・指令は `cp`、契約・制度・参照・比べる線は `lg`。見た目の強調のために種別を変えない。
2. **`plane` を省略しない**（既定に頼らない）。どの線にも明示する（自己点検 4 が `NG` にする）。
3. **同じ線（同じ `id`）の種別を `views` で変えない**。物の流れと信号を両方見せたいときは、別の `id` の線を 2 本引き、`views` で出し分ける。
4. §3 で線の種別を指定した図は、その指定に従う。**線図（`-ts`・`-tq`）は `up` と `lg` だけ**（§6.5。自己点検 4）。
5. `kind` は §6.2 の意味だけ。発電所・建屋・敷地は「入れ物」なので、`kind` を付けずに `groups`（枠）で表す。
6. 自己点検（§8.10 の 4）が全部の線を `図 id・種別・端点・ラベル・運ぶもの` で出力するので、§6.2 の表と 1 行ずつ照らし、完了報告の自己点検表に「線の種別：全 n 本を確認」と書く。

### 8.8 略語の初出

1. **「章の初出」は、章の HTML の先頭から数える**。冒頭の囲み・見出し・図のデータ（本文より先に読者の目に入るもの）を含む。
2. **冒頭の囲みと見出し（`<h3>` `<h4>`）には、まだ説明していない略語を出さない**。日本語で書く（「排熱回収ボイラ」「窒素酸化物」「液化天然ガス」）。どうしても出すときは、その場で正式名を併記する。
3. 略語は、章ごとの初出で `日本語（English full name, 略語）` か、略語が一般名になっている語は `略語（English full name）` の形にする（`GLOSSARY-RULES.md` §3.1）。他の章で定義済みでも、章ごとに併記する。
4. 化学式（CO2・NOx・O2・H2・NH3 など）も略語と同じに扱い、章ごとの初出で「二酸化炭素（CO2）」のように書く。
5. 図のデータの中（`seq` の `msg`、`flow` の工程名、`layers` の部位名）は短くするため略語可。ただし、その章の本文で、その図より前に初出の併記を済ませていること。
6. 自己点検（§8.10 の 6）が、括弧の近くにない初出の候補を出力する。候補はすべて目で確かめる。単位の記号（MW・MPa・MJ など）は候補から除いてある。

### 8.14 法令・制度・社名の確認の手順

法令と制度は、改正・新設・撤回が続く分野です。次の手順で、**国・地域と確認の日**を必ず残します。

1. **国・地域を書く**：本文で制度に触れる段落の最初の文に国・地域を書く（「日本では、…」「EU では、…」）。表（`c28-laws` など）は「国・地域」の列を最初に置く。事実確認表の `制度` の行は【国・地域】で始める（自己点検 12）。
2. **正式名と略称**：日本の法令は e-Gov の題名を正式名として初出に書き、通称は括弧で添える（例：「エネルギーの使用の合理化及び非化石エネルギーへの転換等に関する法律（省エネ法）」。題名は e-Gov で確かめる）。
3. **現行の条文**：e-Gov（海外は EUR-Lex、Federal Register、legislation.gov.uk など）の現行の条文を開き、最終改正の法令名・公布日・施行日を事実確認表の「時点・版」に書く。当局の解説だけで書くときは、条文を開いていないことを書く。
4. **改正の履歴**：確認の日から**さかのぼって 3 年分**の改正・公布・施行予定を、所管の当局の公式ページで確かめる（第2弾の REVIEW-part3 M2 は、古い通知だけで書いていた）。施行の前の改正は「◯年◯月◯日に施行の予定（公布 ◯年◯月◯日）」と書く。
5. **時期の語**：§8.2-16 の語を原文のまま使う。制度の「開始」が、初回の入札の日か、対象の年度の始まりかを区別する。
6. **規模の言葉と単位**：§8.2-4・15。「以上」「超」「未満」「以下」と単位（kW・万 kW・t）を原文のまま。
7. **審議中・係争中**：§8.2-20。段階と確認日を書き、成立を推測しない。
8. **★を付ける**：§3 の Web で★の付いた制度は、公開の直前に検証担当がもう一度開く。
9. **社名・団体名**：§8.12 の変遷の手がかりを、会社概要・沿革・発表で確かめ、事実確認表の `企業` の行に「社名変更：」を書く。出典の時点の社名と現在の社名が違うときは、本文の初出と参照資料の表に「（現◯◯）」を添える。
10. **個別の判断をしない**：§9.3「法令と制度」の定型文を置き、案件ごとの適用・要否・適合を判断しない。
