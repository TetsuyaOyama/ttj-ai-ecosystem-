複数のエージェントを動かす枠組み

マルチエージェント（multi-agent）は、役割の違う複数のエージェントを組み合わせて、1 つの作業を進める方法です。たとえば、調べる役、まとめる役、確かめる役、のように分けます。

この方法を実際に動かすには、フレームワーク（framework、部品と使い方の枠組み）を使います。段階 4 では、フレームワークを選んで、動くサンプルを試します。

この道筋の元の案では、「CrewAI か Microsoft AutoGen」でした。このうち AutoGen は、アーカイブされ、保守が終わっています。新規には、Microsoft Agent Framework が案内されています。AutoGen は、状態の札を付けて、表に残しました。

AutoGen と、後継の Microsoft Agent Framework

AutoGen の README は、プロジェクトがアーカイブされ、Microsoft による保守は終わったと書いています。バグやセキュリティの修正も、新機能も、サポートも提供されません。本番での利用は勧められていません。リポジトリは、歴史と参照のために公開が続いています（出典：Microsoft『AutoGen』README、確認 2026 年 11 月）。

Microsoft Agent Framework の Learn のページは、AutoGen と Semantic Kernel の直接の後継と書いています。AutoGen からの移行ガイドも、用意されています（出典：Microsoft Learn『Microsoft Agent Framework overview』、ページ表示の更新日 2026 年 10 月 28 日）。

表で確かめる点は 3 つです。1 つ目は、状態の違いです。一方は保守が終わり、もう一方は、更新日が 2026 年 10 月 28 日と表示されています。2 つ目は、対応言語です。3 つ目は、移行ガイドがあることです。

なお、2025 年 10 月の公式の発表は、AutoGen の保守を続け、重大なバグとセキュリティの修正は提供する、と書いていました（出典：microsoft/autogen の Discussions #7066、2025 年 10 月 2 日）。2026 年 4 月の記事（二次情報）にも、同じ書き方があります。確認日（2026 年 11 月 15 日）の README は、アーカイブの表示に変わっています。この講座は、提供元の今の README の表示に合わせました。古い記事と今のページが食い違うときは、提供元の今のページを見ます。

段階 4 の教材（選択肢）

段階 4 の選択肢は 5 つです。優劣の順位はつけません。選ぶときは、使う言語、API キーの提供元、状態、ライセンスなど、ページに書かれた事実で決めます。表の行を押して、前提を確かめてください。

用語を整理します。SDK（software development kit）は、ある機能をプログラムから使いやすくするための、道具一式です。ハンドオフは、あるエージェントが、別のエージェントへ作業を引き継ぐことです。ガードレールは、入力や出力を検証して、望まない動きを防ぐ仕組みです。OpenAI Agents SDK のドキュメントは、これらを構成要素として挙げています。

どれを選ぶか：事実で絞る

  • 使う言語：CrewAI と OpenAI Agents SDK は Python です。Microsoft Agent Framework は、Python と .NET です。
  • API キーと利用料：CrewAI の既定は OpenAI の API です。OpenAI Agents SDK の例は、OPENAI_API_KEY を使います。どちらも、利用料がかかる場合があります。
  • 状態：AutoGen は、保守終了です。新規には勧めません。
  • 動くサンプルを見たい：Awesome LLM Apps は、100 以上のサンプルを集めた、個人のリポジトリです。公式の教材ではありません。

これらは、優劣ではなく、前提の違いです。自分が使える言語と、API キーの持ち方で、候補を絞ります。

終えるとできること（段階 4）

この段階の教材を 1 つ動かすと、次のことに取り組めるようになります。保証ではなく、目安です。

  • 複数のエージェントに役割を割り当てる、小さなサンプルを動かせる。
  • 保守終了や、後継への移行といった、フレームワークの状態の変化を、札から読み取れる。
  • 自分の作業に合うフレームワークを、前提の違いから絞れる。
次へ進む目安

サンプルを動かして、エージェントごとの役割と、1 回あたりにかかる API の利用料の見積もりを、自分の言葉で説明できたら、先へ進みます。任意の段階（第 06 章）か、自分の環境づくり（第 07 章）です。

つまずきやすい点

保守終了の枠組みを、新規に選ぶことです。検索すると、AutoGen の古い解説が、たくさん見つかります。解説の日付と、提供元の README の状態を、先に確かめます。

もう 1 つは、動かす回数が増えて、API の利用料が増えることです。複数のエージェントは、それぞれが API を呼びます。繰り返しの回数の上限と、費用の上限を、先に決めます。
