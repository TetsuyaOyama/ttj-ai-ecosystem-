なぜ、1 台を分け合うのか

サーバーを、1 つの用途に 1 台ずつ割り当てると、使われない時間が多くなります。多くの仕事は、常に機器の全力を使うわけではないからです。そこで、1 台の物理サーバーを複数の用途で分け合い、利用率を上げます。

分け合うことには、利用率のほかに 2 つの利点があります。1 つは分離で、ある用途の不具合や設定の変更が、ほかの用途に及びにくくなります。もう 1 つは移動で、用途を、別の物理サーバーへ移せます。機器の保守や、負荷の偏りの解消に役立ちます。

この仕組みを仮想化（virtualization）と呼びます。物理的な機器の資源（CPU・メモリ・ストレージ・ネットワーク）を、ソフトウェアで分け、複数の独立した環境として見せる技術です。

ハイパーバイザと仮想マシン

仮想マシン（Virtual Machine, VM）は、ソフトウェアで作った「仮想のコンピュータ」です。VM ごとに、独立した OS（ゲスト OS）を動かせます。VM を作り、物理サーバーの資源を割り当てる役目のソフトウェアが、ハイパーバイザ（hypervisor）です。

ハイパーバイザには、置き方で 2 つの型があります（一般知識）。

  • type 1：ハードウェアの上で直接動きます。データセンターの仮想化の基盤で使われる形です。
  • type 2：ふつうの OS の上のアプリケーションとして動きます。個人の PC での試験などで使われる形です。

Linux には、Linux 自身をハイパーバイザとして使う機能があります。KVM（Kernel-based Virtual Machine、Linux のハイパーバイザ）と呼びます。なお、第19章に出てくるリモートコンソールの「仮想 KVM」（Keyboard, Video, Mouse）は、別の意味の略語です。

VM は、ゲスト OS ごとに分かれるので、分離の強さに優れます。反面、VM ごとに OS を動かすので、メモリと起動時間の負担が増えます。

コンテナとイメージ

コンテナ（container）は、アプリケーションとその動作に必要なファイル群を 1 つにまとめ、他と分けて動かす方式です。VM と違い、コンテナはホスト OS のカーネルを共有します。OS 全体を動かさないので、軽く、すぐ起動します。反面、カーネルを共有するので、VM ほどの強い分離は持ちません。

コンテナのひな形をコンテナイメージ（container image）と呼びます。同じイメージから、同じ環境を何個でも起動でき、別の機器へ持ち運べます。イメージの形式と実行の仕様は、OCI（Open Container Initiative）の仕様が広く使われます（一般知識。仕様の版は確認していません）。

オーケストレーション：台数が増えたときの管理

コンテナは軽いので、数が大きく増えます。数百、数千のコンテナを、人が 1 つずつ起動・停止・移動するのは現実的ではありません。そこで、コンテナの配置、再起動、台数の増減を、自動で行う仕組みが使われます。これをオーケストレーション（orchestration）と呼びます。

代表的なソフトウェアが Kubernetes です。コンテナを、どの機器で動かすか、止まったらどうするかを、宣言した状態に合わせて自動で保ちます。Kubernetes は、Linux Foundation の一部である CNCF（Cloud Native Computing Foundation）のプロジェクトで、2018 年 3 月 6 日に、CNCF で最初の「卒業」（graduated）の段階のプロジェクトになりました（出典：CNCF の発表、2018 年 3 月 6 日）。資源の割り当てや GPU の扱いの詳細は、第22章で扱います。

ベアメタル・VM・コンテナの使い分け

物理サーバーを、仮想化せずに、直接 1 つの用途へ割り当てる形をベアメタル（bare metal）と呼びます。3 つの形は、優劣ではなく、用途で選びます。

  • ベアメタル：ハードウェアを専有したいとき。性能のばらつきを避けたいとき、特殊なハードウェアの機能を直接使いたいときに選びます。
  • VM：用途ごとに、OS から分けたいとき。分離を強くしたいとき、異なる OS を同じ機器で動かしたいときに向きます。
  • コンテナ：同じ OS 上で、軽く、多数動かしたいとき。起動の速さと、持ち運びの容易さが活きます。

実際には、組み合わせます。たとえば、VM の中でコンテナを動かす形は、分離と軽さの両方を取りたいときの選択肢です。

クラウドの提供形態：IaaS・PaaS・SaaS

クラウドは、仮想化された資源を、利用者が必要なだけ借りて使うサービスです。何を事業者が管理し、何を利用者が管理するかで、3 つの提供形態に分けて呼ぶのが一般的です。米国国立標準技術研究所（NIST）の SP 800-145『The NIST Definition of Cloud Computing』（2011 年 9 月 28 日公表）は、クラウドを、5 つの本質的な特徴、3 つのサービスモデル、4 つの配置モデルで定義しています。3 つのサービスモデルが、次の IaaS・PaaS・SaaS です（出典：NIST CSRC『SP 800-145』のページ）。

  • IaaS（Infrastructure as a Service）：計算機、ストレージ、ネットワークを借ります。OS より上は、利用者が管理します。
  • PaaS（Platform as a Service）：アプリを動かす基盤を借ります。利用者は、アプリとデータを管理します。
  • SaaS（Software as a Service）：完成したソフトウェアを、サービスとして使います。

1 つの物理サーバーを、複数の利用者が分け合う形をマルチテナント（multi-tenancy）と呼びます。分離が守られることが、前提になります。

GPU の共有：入口

GPU のようなアクセラレータは、高価で、数が限られます。そこで、1 つの GPU を、複数の利用者や用途で分けて使う工夫があります。主な方法は 2 つです。1 つの GPU を、ある VM に丸ごと渡す方法（パススルー）。もう 1 つは、1 つの GPU を、複数の部分に分けて割り当てる方法（GPU の分割）です。分割の機能は、各社が独自の名前で提供しています。仕組みと割り当ての方針は、第22章で扱います。

演習：3 つの用途で、何から考えるか

次の 3 つの用途（架空）について、ベアメタル・VM・コンテナのどれから考えるかを、理由つきで選んでください。考えてから、答えを開きます。

  1. A 社の、小さな Web サービス。利用者の数が日によって大きく変わり、機能を毎週更新する。
  2. B 社の、社内システム。古い OS のまま動かしたい業務ソフトが 2 つあり、互いに干渉させたくない。
  3. C 社の、大規模な AI の学習。複数の GPU サーバーを占有し、通信の性能を安定させたい。
答えを見る

① コンテナから考えます。更新が多く、数を増減したいので、軽く起動が速いコンテナと、オーケストレーションが合います。

② VMから考えます。古い OS を、業務ソフトごとに分けて動かせます。OS 単位で分離でき、干渉を防げます。

③ ベアメタルから考えます。ハードウェアを専有し、性能のばらつきを避けたいからです。実際には、ベアメタルの上でコンテナを動かす構成も多く、選択肢は 1 つに限りません。

これは、考える順序の練習で、唯一の正解ではありません。実際は、運用の体制や費用も加えて決めます。

つまずきやすい点

コンテナは VM の軽い版、ではありません。VM は OS ごと分けます。コンテナは、OS のカーネルを共有して、プロセスを分けます。分離の強さと軽さは、引換えになります。

もう一つ。KVM は、略語が 2 つあります。Linux のハイパーバイザの KVM と、リモートコンソールの KVM は別の意味です。

現場でのつながり

仮想化は、機器の選び方に効きます。VM やコンテナを多数動かす基盤は、CPU のコア数とメモリの容量が重要になります。GPU を分けて使う基盤は、GPU の分割と、運用の仕組み（第22章）が選定の条件に入ります。
