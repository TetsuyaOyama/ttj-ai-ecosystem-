Kiの保護とトランスポートキー 実務手順

このページの位置づけ

業界で一般的な進め方を、実務の手順の形にまとめたものです。特定のMNO、サプライヤー、装置の正式な手順ではありません。暗号の方式、部品の数、書式、装置の操作は、MNOとサプライヤーの取り決めと、装置のメーカーの手順に従ってください。図は説明のために作成したもので、図の中の値はすべてテスト用です。

1はじめに

何を守るのか

Kiは、SIMと通信網がお互いを確かめるための秘密の鍵です。同じ値が、カードの中とMNOの加入者データベースの両方に入ります。Kiが漏れると、そのSIMになりすますことや、通信を盗み聞くことができてしまいます。

Kiはサプライヤーが製造のときに作ります。MNOへ伝えるためにOutput Fileに入れますが、そのままの値では入れません。あらかじめ双方で共有した「トランスポートキー」で暗号化して入れます。

用語

用語意味
KiSIMごとの認証鍵。128ビット（16進数で32桁）。OPcなど、同じ扱いをする値もある
トランスポートキーMNOとサプライヤーが共有する秘密の共通鍵。Kiを暗号化して運ぶために使う
HSM鍵を中に閉じ込めて暗号処理を行う専用の装置。鍵は装置の外に出ない
部品（コンポーネント）鍵を分割したもの。全部そろわないと鍵にならない
KCV（確認値）鍵や部品を正しく受け取れたかを確かめる短い値。通常は16進数で6桁
鍵管理者（カストディアン）部品を1つだけ預かる担当者
キーセレモニー鍵を作る、分ける、装置へ入れる作業を、複数人の立ち会いで行う場

守るべき3つの原則

  • 一人では扱えないようにする。鍵にかかわる作業は、必ず2人以上で行います。
  • 一人が全体を知らないようにする。鍵を部品に分け、1人が持つのは1つだけにします。
  • すべて記録する。いつ、誰が、何をしたかを記録し、立会人が署名します。

全体の流れ

2体制と準備

役割

役割MNO側サプライヤー側
鍵責任者作業全体を計画し、承認する同じ
鍵管理者（2〜3名）部品を1つずつ作り、封筒に入れて送る部品を1つずつ受け取り、HSMへ入力する
HSM管理者装置を操作できる状態にする同じ
立会人手順どおりに行われたかを見て、記録に署名する同じ

兼ねてはいけない組み合わせ

鍵管理者どうしは、上司と部下の関係にしない、互いの部品を預からない、という形にします。HSM管理者が鍵管理者を兼ねることも避けます。

用意するもの

  • HSM（MNO側、サプライヤー側のそれぞれ）
  • 開封した跡が残る封筒（部品の数だけ）
  • 部品を保管する金庫（鍵管理者ごとに別のもの、または別の区画）
  • 入退室を管理できる部屋。外部のネットワークにつながっていない環境
  • 記録の用紙（このページの8章）

事前に決めること

項目決める内容の例
暗号の方式と鍵の長さAES（128ビット）または3DES。MNOの加入者データベースが対応する方式に合わせる
Kiの暗号化の方法1つのKiを1つのまとまりとして暗号化する方法が一般的。詳細はMNOの仕様に従う
部品の数2個または3個
KCVの計算方法方式によって違う。双方で同じ方法を使う
鍵の番号Output Fileのヘッダーに書く番号（例：01）
有効期限と更新の時期例：2年ごと。更新の手順も決めておく
部品の届け方書留、手渡しなど。部品ごとに別の経路にする

3手順A：鍵を作って分ける（MNO）

  1. 鍵責任者、鍵管理者、HSM管理者、立会人が、決められた部屋に集まります。入室を記録します。
  2. HSM管理者が、HSMを鍵の生成ができる状態にします。
  3. HSMで、トランスポートキーを生成します。鍵は装置の中で作られ、外には出ません。
  4. HSMの機能で、鍵を部品に分けて出力します。鍵管理者は1人ずつ装置の前に立ち、自分の部品とそのKCVだけを受け取ります。ほかの人は画面と手元を見ません。
  5. 鍵全体のKCVを記録します。この値はあとで、サプライヤーへ別の経路で伝えます。
  6. 鍵に番号を付けて、記録します。
  1. 各鍵管理者が、自分の部品を封筒に入れ、封をします。封筒の外には、封筒番号、宛先、KCVだけを書きます。
  2. 封筒を、それぞれの金庫に保管します。
  3. 立会人が、記録の用紙に署名します。

やってはいけないこと

部品を写真に撮る、メールやチャットに書く、パソコンのファイルに保存する、複数の部品を1人で持つ。どれか1つでも行うと、鍵を作り直す必要があります。

4手順B：部品を届ける

  1. MNOの鍵責任者が、サプライヤーの鍵責任者へ、送る日と方法を連絡します。部品の中身は伝えません。
  2. 各封筒を、宛先の鍵管理者へ、別々の経路で送ります。日もずらします。
  3. サプライヤーの鍵管理者は、本人が受け取ります。代理の受け取りはしません。
  4. 受け取ったら、封印が破られていないかを確かめ、封筒番号を控え、受領書に署名してMNOへ返します。
  5. 封筒は開けずに、自分の金庫に保管します。開けるのはキーセレモニーの当日です。
  6. 鍵全体のKCVは、部品とは別の経路（電話や別便の書面）で、鍵責任者どうしが伝えます。

封印が破られていた場合

その鍵は使いません。MNOへ連絡し、手順Aからやり直します。ほかの部品が無事でも同じです。

5手順C：HSMへ入れる（サプライヤー）

  1. 鍵責任者、鍵管理者全員、HSM管理者、立会人が集まります。入室を記録します。
  2. 立会人が、全員の封筒の封印と封筒番号を確かめます。
  3. HSM管理者が、HSMを鍵の部品を受け付ける状態にします。
  4. 鍵管理者Aが封筒を開け、自分の部品を入力します。画面に出たKCVが、封筒のKCVと同じであることを確かめます。ほかの人は画面と手元を見ません。
  5. 鍵管理者B、Cも、同じように入力します。
  6. HSMが部品を組み立て、鍵全体のKCVを表示します。MNOから聞いたKCVと一致することを、鍵責任者と立会人が確かめます。
  7. 一致したら、決められた鍵番号で鍵を登録します。
  8. 使い終わった部品の紙は、取り決めに従って、その場で裁断するか、封をし直して金庫へ戻します。
  9. 立会人が、記録の用紙に署名します。

KCVが一致しない場合

入力の誤りが最も多い原因です。組み立てた鍵を消し、最初の部品から入力し直します。それでも一致しない場合は、MNOへ連絡します。一致しない鍵は使いません。

6手順D：動作を確かめる

本番の前に、テスト用の値で、暗号化と復号が双方で同じ結果になることを確かめます。

  1. MNOとサプライヤーで、テスト用のKi（本番では使わない値）を決めます。
  2. サプライヤーが、HSMでテスト用のKiをトランスポートキーで暗号化し、結果をMNOへ伝えます。
  3. MNOが、HSMでそれを復号し、テスト用のKiに戻ることを確かめます。
  4. 続けて、テスト用のOutput File（数件）を作り、MNOの取り込みの仕組みで読み込めることを確かめます。
  5. 結果を記録し、双方の鍵責任者が本番の利用を承認します。

7手順E・F：製造と取り込み

手順E：製造のとき（サプライヤー）

  1. HSMが、カードごとにKiを乱数で作ります。
  2. Kiをカードへ書き込みます。この処理は、管理された製造ラインの中だけで行います。
  3. 同じKiを、HSMの中でトランスポートキーで暗号化します。
  4. 暗号化された値を、Output Fileの各行に書きます。ヘッダーには、使ったトランスポートキーの番号を書きます。
  5. Output Fileの件数と番号の範囲を、発注の内容と照合します。
  6. Output Fileを、取り決めた方法（PGPでの暗号化、SFTPなど）でMNOへ送ります。

書式はサプライヤーとMNOの取り決めで決まります。図は一例で、項目の名前や並びは実際と違う場合があります。

手順F：取り込み（MNO）

  1. Output Fileを受け取り、ファイル全体の暗号化を解きます。送り主の署名を確かめます。
  2. ヘッダーの件数、番号の範囲、トランスポートキーの番号が、発注の内容と合っていることを確かめます。
  3. 取り込みの仕組みにファイルを渡します。HSMが、指定された番号の鍵でKiを復号し、加入者データベース用の保管鍵で暗号化し直します。
  4. 取り込まれた件数を確かめます。
  5. サプライヤーへ受領と取り込み完了を連絡します。
  6. 作業用のファイルを削除します。

トランスポートキーの番号が違うと

復号した値がでたらめになり、そのSIMは通信網で認証できません。取り込み自体は成功したように見えることがあるため、サンプルのカードで実際に接続できることを確かめます。

8鍵の管理と記録

鍵の一生

場面行うこと
番号の管理鍵ごとに番号、作成日、KCV、有効期限、使っているオーダーを台帳に記録する
更新期限の前に、新しい鍵を手順A〜Dで用意する。新旧を切り替える日を双方で決める
漏れた疑いすぐに相手へ連絡し、その鍵の利用を止める。その鍵で送ったOutput Fileの範囲を調べる

9計算の例（テスト用の値）

仕組みを確かめるための例です。こちらで実際に計算して、暗号化した値を復号すると元に戻ることを確認しています。方式はAES（128ビット）で、KCVは「すべて0の16バイトを暗号化した結果の先頭3バイト」としています。実際の方式とKCVの計算方法は、取り決めに従ってください。

項目値
部品13A7F91C204D85E6B19A0F3472CDE8815　（KCV 24FF8E）
部品2C4129E55B0637A0D8F21D46E90B75C3A　（KCV 2B8606）
部品35D0E46A1F7239BC8E1640A9D33F217E6　（KCV 20B3A2）
トランスポートキー（3つを重ねた値）A36349364398BFAE77E52DB48F9BC3C9　（KCV 9455CA）
テスト用のKi000102030405060708090A0B0C0D0E0F
暗号化されたKi315CA2F0DCE14DA2E9A82C15F7FBDDB2

本物の鍵で同じ計算をしない

この例は、パソコンで計算できるテスト用の値です。本物の鍵と部品は、HSMの中だけで扱います。表計算ソフトやプログラムに入力しません。

10確認の一覧と、よくある失敗

作業の前に

  • 暗号の方式、部品の数、KCVの計算方法を、双方で文書にして合意したか
  • 鍵管理者と立会人を、名簿で相手に伝えたか
  • 部品の届け方を、部品ごとに別の経路にしたか

作業のあとに

  • KCVが一致したことを、記録に残したか
  • テスト用の値で、暗号化と復号を双方で確かめたか
  • 部品の紙を、取り決めどおりに裁断または保管したか
  • 鍵の台帳を更新したか

よくある失敗

起きること原因防ぎ方
KCVが一致しない部品の入力の誤り、KCVの計算方法の違い入力は読み上げて2回確かめる。計算方法を事前に合意する
取り込んだSIMが認証できない鍵の番号の取り違え、暗号の方式の違いテスト用のOutput Fileとサンプルのカードで事前に確かめる
部品が1人に集まる担当者の不在で代理が受け取った代理の受け取りを禁止する。不在なら日を改める
古い鍵で暗号化したファイルが届く鍵の切り替え日の認識の違い切り替え日を文書で合意し、ヘッダーの鍵番号を必ず確かめる
