eSIM / SIM — 実務ノート

MNOとeUICC Supplierの安全なやり取り 解説と手順

MNOとeUICC Supplier（SIMの製造会社）の間で、どの情報を、どう守って受け渡しているかをまとめた解説と手順です。取引を始めるときの準備と、毎回のオーダーの手順に分けて説明します。

このページの位置づけ

業界で一般的な進め方を、実務の手順の形にまとめたものです。特定のMNO、サプライヤー、装置の正式な手順ではありません。暗号の方式、部品の数、書式、装置の操作は、MNOとサプライヤーの取り決めと、装置のメーカーの手順書に従ってください。図は説明のために作成したもので、図の中の値はすべてテスト用です。

3つの守り

Output Fileは、この3つを重ねて守ります。中の鍵（Ki）の暗号化は必ず行います。通り道とファイル全体の守り方は、MNOとサプライヤーの取り決めで決まります。

前提となる仕組み

  • 秘密保持契約。扱う情報の範囲、目的、保管の期間、事故のときの連絡を定めます。
  • 製造拠点の認定。SIMの製造拠点には、業界団体（GSMA）による安全管理の認定制度があります。MNOは、認定を受けた拠点であることを取引の条件にすることが一般的です。
  • 窓口の限定。ファイルや鍵を扱える担当者を名簿で決め、相手に伝えます。

2取引を始めるときの準備

手順1　契約と認定を確かめる

  1. 秘密保持契約を結びます。
  2. サプライヤーの製造拠点の認定の状況と、有効期限を確かめます。
  3. 情報の保管の期間と、消し方を決めます。

手順2　窓口を登録する

  1. 双方で、ファイルを扱う担当者、鍵責任者、鍵管理者の名簿を作り、交換します。
  2. 緊急のときの連絡先（電話）を決めます。
  3. 担当者が替わったときの届け出の方法を決めます。

手順3　経路をつなぐ

  1. ファイルの受け渡しの方法を決めます（SFTP、専用線、サプライヤーが用意する受け渡し用のサイトなど）。
  2. 接続できる相手を、双方のIPアドレスで限定します。
  3. 接続用の鍵を交換し、サーバーの指紋を確かめます。
  4. テスト用のファイルで、送信と受信を確かめます。

手順4　鍵を交換する

  1. ファイル全体を暗号化する場合は、PGPの公開鍵を交換し、電話で指紋を読み合わせます。
  2. トランスポートキーを、部品に分けて別々の経路で届け、サプライヤーのHSMへ入れます。確認値（KCV）を照合します。
  3. テスト用の値で、暗号化と復号が双方で同じ結果になることを確かめます。

トランスポートキーの詳しい手順は、「Kiの保護とトランスポートキー」のページにまとめています。

手順5　仕様を決める

  1. プロファイルの仕様（ファイルの構成、認証の方式、初期値）を決めます。
  2. Input FileとOutput Fileの書式（項目、並び、区切り、ヘッダー）を決めます。
  3. 番号の範囲（ICCID、IMSI）の割り当て方を決めます。

手順6　テストする

  1. テスト用のInput Fileを送り、サプライヤーが読み込めることを確かめます。
  2. サプライヤーがテスト用のOutput Fileとサンプルのカードを作ります。
  3. MNOがOutput Fileを取り込み、サンプルのカードが通信網で認証できることを確かめます。

手順7　本番を承認する

  1. テストの結果を記録し、双方の責任者が署名します。
  2. 本番の運用を始める日を決めます。

3毎回のオーダーの手順

手順1　発注する（MNO）

  1. 数量、プロファイルの種類、納期、納品先を決め、発注します。
  2. ICCIDとIMSIの範囲を割り当てます。ほかのオーダーと重ならないことを確かめます。

手順2　Input Fileを送る（MNO）

  1. 決めた書式でInput Fileを作ります。
  2. 件数と番号の範囲を、発注の内容と照合します。別の担当者がもう一度確かめます。
  3. 取り決めた方法で送ります。
  4. サプライヤーから受領の連絡を受けます。

手順3　製造する（Supplier）

  1. Input Fileを読み込み、件数と範囲を発注と照合します。
  2. HSMでKiを生成し、カードへ書き込みます。
  3. 同じKiをトランスポートキーで暗号化し、Output Fileを作ります。
  4. サンプルのカードで、書き込んだ内容を確かめます。

手順4　Output Fileを送る（Supplier）

  1. Output Fileの件数と範囲を、Input Fileと照合します。
  2. ファイル全体を暗号化します（取り決めによる）。
  3. 取り決めた方法で送ります。
  4. MNOから受領の連絡を受けます。

手順5　取り込む（MNO）

  1. 送り主の署名を確かめ、ファイル全体の暗号化を解きます。
  2. ヘッダーの件数、範囲、トランスポートキーの番号を確かめます。
  3. 取り込みの仕組みに渡し、加入者データベースへ登録します（Provisioning）。
  4. 取り込まれた件数を確かめ、サプライヤーへ完了を連絡します。

手順6　納品と後始末

  1. サプライヤーが、封印した箱でカードを出荷します。箱の番号と数量を納品書に書きます。
  2. 納品先が、封印の状態と数量を確かめ、受領を連絡します。
  3. 双方で、作業用のファイルを削除します。保管が必要なものは、決められた場所だけに置きます。
  4. オーダーの記録（日時、担当者、件数、ファイルの照合用の値）を保管します。

5eSIM（eUICC）の場合：3つの形

eSIMでは、プロファイルをいつ、どこからeUICCへ入れるかによって、やり取りが3つの形に分かれます。どの形でも、2章から4章の内容（契約、経路、鍵の交換、Input FileとOutput File）は土台として使います。この章では、形ごとに加わる部分を説明します。

5-1　eSIMで共通して変わること

  • サプライヤーの役目が2つに分かれる。eUICCという部品を作る会社と、プロファイルを作って保管するサーバーの運用会社です。同じ会社が両方を担うこともあります。
  • eUICCの固有番号（EID）を扱う。どのeUICCへ配るかを、EIDで指定します。
  • 証明書で相手を確かめる。サーバーとeUICCは、業界共通の認証の仕組みで発行された証明書を使い、お互いが本物かを確かめます。
  • オンラインのやり取りが加わる（形BとC）。MNOの業務システムとサーバーをつなぎます。接続元の制限と、証明書による相互の確認を行います。
形A：工場で書き込み済み形B：SM-DP+形C：SM-DP と SM-SR
主な用途物理SIMと同じ扱いのeUICCスマートフォン、新しいIoT機器従来の車載・産業機器（M2M）
サーバーなしSM-DP+SM-DP と SM-SR
配り方配らない端末側が取りに行くサーバー側から送り込む
MNOがつなぐ相手SupplierのみSM-DP+（ES2+）SM-DP（ES2）、SM-SR（ES4）
Output Fileありあり（一般的）あり（一般的）
準備に加わることほぼなしSM-DP+との接続、受け取り用コードの渡し方SM-SRとの契約と接続、eUICC情報の登録

5-2　形A：工場で書き込み済み

製造のときにプロファイルをeUICCへ書き込み、そのまま出荷する形です。eUICCは部品として機器の製造会社へ届き、機器に組み込まれます。

準備と毎回の手順

  1. 2章の準備と、3章の毎回の手順を、そのまま行います。
  2. 納品先がMNOではなく機器の製造会社になる場合は、納品先、数量、箱の番号を、発注のときに取り決めます。
  3. 機器の製造会社が受け取るのは、eUICCの現物だけです。Output Fileは、SupplierとMNOの間で完結します。

5-3　形B：SM-DP+ を使う方式

プロファイルをSM-DP+というサーバーに保管し、端末側から受け取りに行く形です。スマートフォンのeSIMがこの形です。新しいIoT機器向けの方式でも、同じSM-DP+を使います。

準備で加わること

  1. SM-DP+の運用会社と契約します。SM-DP+の拠点にも、安全管理の認定制度があります。
  2. MNOの業務システムとSM-DP+を、ES2+というインターフェースでつなぎます。双方の証明書を交換し、接続元を限定します。
  3. プロファイルのひな型（種類）をSM-DP+に登録し、テスト用のeUICCで受け取りを確かめます。
  4. 受け取り用のコード（SM-DP+の宛先と、注文を指す番号の組）を、誰に、どう渡すかを決めます。

毎回の手順で加わること

  1. Input Fileに相当する情報（ICCID、IMSIの範囲、プロファイルの種類）を渡し、SM-DP+側でプロファイルを用意してもらいます。
  2. Output Fileを受け取り、加入者データベースへ登録します。ここまでは3章と同じです。
  3. ES2+で注文します（DownloadOrder）。配る先のeUICCが決まっている場合は、EIDを指定します。
  4. ES2+で確定します（ConfirmOrder）。受け取り用のコードが決まります。
  5. 受け取り用のコードを、端末を扱う側へ渡します。
  6. 端末がSM-DP+へ取りに行きます。SM-DP+とeUICCが証明書で確かめ合い、そのeUICC専用に暗号化されたプロファイルが配信されます。
  7. SM-DP+から、結果の通知を受け取ります。
  8. 配る前に取りやめる場合は、ES2+で取り消します（CancelOrder）。
守るもの守り方
MNOとSM-DP+の接続双方の証明書で確かめ合う通信、接続元の制限、利用者と権限の管理
受け取り用のコード注文ごとに別の値にする。EIDを指定して、ほかのeUICCでは受け取れないようにする。渡す相手を限定する
配信するプロファイル配る先のeUICCだけが開けるように暗号化する（SM-DP+が行う）
Kiこれまでどおり、トランスポートキーで暗号化してOutput Fileで受け取る

IoT機器向けの場合

画面の無い機器では、利用者の代わりに、遠隔の管理サーバーが受け取りを指示します。この管理サーバーを誰が運用するか、どの機器を管理できるかが、新しい取り決めの対象になります。

5-4　形C：SM-DP と SM-SR を使う方式（M2M）

プロファイルをSM-DPというサーバーで用意し、SM-SRというサーバーがeUICCへ送り込む形です。従来の車載機器や産業機器で使われてきました。eUICCを遠隔で操作するための鍵は、SM-SRが持ちます。

準備で加わること

  1. SM-DPの運用会社、SM-SRの運用会社と、それぞれ契約します。同じ会社の場合もあります。
  2. MNOの業務システムを、SM-DP（ES2）とSM-SR（ES4）へつなぎます。証明書の交換と、接続元の限定を行います。
  3. eUICCの製造会社が、eUICCごとの情報（EID、操作用の鍵など）をSM-SRへ登録していることを確かめます（ES1）。この登録が無いeUICCには、プロファイルを送り込めません。
  4. 出荷時に入れておく接続用のプロファイル（最初にSM-SRへつなぐためのもの）を、誰が提供するかを決めます。
  5. プロファイルの切り替えを誰が指示できるかの規則を決めます。
  6. テスト用のeUICCで、送り込み、有効化、無効化、削除を確かめます。

毎回の手順で加わること

  1. プロファイルの用意を依頼し、Output Fileを受け取って、加入者データベースへ登録します。ここまでは3章と同じです。
  2. ES2で、配る先のEIDを指定してダウンロードを依頼します（DownloadProfile）。
  3. SM-DPがSM-SRと連携し（ES3）、eUICCの中にプロファイルの入れ物を作って、プロファイルを送り込みます。
  4. プロファイルを有効にします（EnableProfile）。ES2経由、またはES4でSM-SRへ直接指示します。
  5. 結果の通知を受け取り、機器が新しいプロファイルで通信網へつながることを確かめます。
守るもの守り方
MNOとSM-DP、SM-SRの接続双方の証明書で確かめ合う通信、接続元の制限、利用者と権限の管理
eUICCごとの情報（操作用の鍵を含む）eUICCの製造会社からSM-SRへ、保護された経路で登録する。MNOは直接は扱わない
送り込むプロファイルSM-DPとeUICCの間で暗号化する。途中のSM-SRは中身を読めない
プロファイルの切り替えの指示指示できる会社を規則で限定し、記録を残す
Kiこれまでどおり、トランスポートキーで暗号化してOutput Fileで受け取る

SM-SRを別の会社へ切り替えるとき

SM-SRの切り替えは、eUICCを操作する鍵の受け渡しを伴う、大きな作業です（ES7）。新旧のSM-SRの運用会社とMNOの3者で、手順、日程、失敗したときの戻し方を取り決めます。

5-5　自社の案件がどの形かを見分ける

確かめること当てはまる形
eUICCが、プロファイルを入れた状態で機器の製造会社へ届く。MNOはSupplierとファイルをやり取りするだけ形A
端末や管理サーバーが、受け取り用のコードやSM-DP+の宛先を使ってプロファイルを取りに行く形B
MNOがEIDを指定して、サーバー側からプロファイルを送り込む。SM-SRという会社が登場する形C

1つの案件で、形を組み合わせることもあります。たとえば、出荷時は形Aで接続用のプロファイルを入れておき、販売する国が決まってから形Cで現地のプロファイルを送り込む、という使い方です。

6うまくいかなかったとき

起きたこと対応
ファイルを別の相手へ送ってしまったすぐに責任者と相手へ電話で連絡する。送った範囲を特定する。Kiは暗号化されているが、その番号の範囲の作り直しを検討する
件数や範囲が合わない取り込みや製造を止める。原因が分かるまで進めない。直したファイルは、版が分かる名前で送り直す
署名が確かめられないファイルを使わない。送り主に電話で確認する
鍵が漏れた疑いがある相手へ連絡し、その鍵の利用を止める。その鍵で守ったファイルの範囲を調べ、新しい鍵を用意する
納品の箱の封印が破られていた受け取りを保留し、サプライヤーへ連絡する。数量と番号を調べる

連絡は電話で

事故の連絡と、相手が本物かの確認は、メールへの返信ではなく、名簿にある電話番号で行います。

8確認の一覧

取引を始めるとき

  • 秘密保持契約と、製造拠点の認定を確かめたか
  • 担当者と鍵管理者の名簿を交換したか
  • 経路の接続元を限定し、テストの送受信をしたか
  • 公開鍵の指紋を電話で確かめたか
  • トランスポートキーの確認値が一致し、テスト用の値で確かめたか
  • サンプルのカードが通信網で認証できたか

毎回のオーダー

  • 番号の範囲が、ほかのオーダーと重なっていないか
  • Input File、Output File、発注の件数と範囲が一致しているか
  • トランスポートキーの番号が正しいか
  • 受領の連絡を双方で交わしたか
  • 作業用のファイルを削除したか
