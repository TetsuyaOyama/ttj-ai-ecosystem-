PGP暗号化とSFTP送信の手順

機密ファイルを、PGPで暗号化し、メールまたはSFTPで相手へ渡す手順です。前半がPGP、後半がSFTPです。初めての方でも進められるように書いています。

1はじめに

PGPとSFTPの役割

PGPSFTP
守るものファイルそのもの。届いたあとも、受け手の秘密鍵が無いと開けない送っている最中の通り道だけ。届いたあとのファイルは守らない
使う鍵受け手の公開鍵で暗号化し、受け手の秘密鍵で復号するSSHの鍵で、接続してよい相手かを確かめる
このページでの使い方必ず行うメールの代わりに使う場合に行う

機密ファイルは、まずPGPで暗号化します。そのうえで、メールに添付するか、SFTPで送ります。SFTPで送る場合も、PGPの暗号化は省きません。

このページの登場人物

  • 送り手：ファイルを暗号化して送る側（暗号化する側）
  • 受け手：ファイルを受け取って復号する側（復号する側）

どちらの立場でも使えるように、両方の作業を書いています。

大事な注意（最初に読んでください）

秘密鍵は誰にも渡さない

相手に渡すのは公開鍵だけです。秘密鍵とそのパスフレーズは、メールにもチャットにも書きません。相手から「秘密鍵を送ってほしい」と言われても、応じないでください。

公開鍵は、指紋を確かめてから使う

メールで届いた公開鍵が、本当に相手のものとは限りません。電話など別の手段で指紋（40桁の英数字）を読み合わせてから使います。

秘密鍵の控えを取る

秘密鍵を失うと、過去に受け取ったファイルも含めて、二度と開けられなくなります。決められた安全な場所に控えを保管します。

ソフトの導入は社内ルールに従う

このページでは、無料で広く使われているGpg4win（Kleopatra）とWinSCPを例にしています。会社のパソコンへ入れるには、管理者の権限や社内の申請が必要な場合があります。

このページの前提

ボタンやメニューの名前は、一般的な版をもとに書いています。お使いの版で名前が違う場合は、同じ意味の項目を探してください。相手の会社が指定する方式がある場合は、そちらを優先します。

2前半：PGPで暗号化する

2-1　ソフトを入れる（最初の1回だけ）

  1. 公式サイト https://www.gpg4win.org/ から、Gpg4winのインストーラーをダウンロードします。
  2. インストーラーを実行します。部品の選択画面では、Kleopatra と GpgEX にチェックが入っていることを確かめます。
  3. 完了したら、スタートメニューから Kleopatra を起動します。

2-2　自分の鍵ペアを作る（最初の1回だけ）

送り手も受け手も、自分の鍵ペア（公開鍵と秘密鍵）を1組作ります。

  1. Kleopatraで「ファイル」→「新しいOpenPGP鍵ペア」を選びます。
  2. 名前（図の①）とメールアドレス（図の②）を入れます。個人名ではなく、業務用の窓口名と共有アドレスにすると、担当者が替わっても使えます。
  3. 「生成した鍵をパスフレーズで保護する」にチェックを入れます（図の③）。
  4. 「詳細設定」を開き（図の④）、有効期限を設定します（例：2年）。
  5. 「OK」を押します。
  1. パスフレーズを2回入力します。長く、他で使っていないものにします。

パスフレーズを忘れない

パスフレーズを忘れると、秘密鍵を使えなくなります。社内の決められた方法（パスワード管理の仕組みなど）で保管します。

2-3　自分の公開鍵を相手に渡す（最初の1回だけ）

  1. 一覧で自分の鍵を選びます（図の①）。
  2. 「エクスポート」を押します（図の②）。
  3. 分かりやすい名前（例：sender_public.asc）で保存します。
  4. 保存したファイルを、メールなどで相手に送ります。公開鍵は見られても問題ありません。

「秘密鍵のエクスポート」は選ばない

メニューには秘密鍵を書き出す項目もあります。相手に渡すために使うことはありません。

2-4　相手の公開鍵を取り込む（最初の1回だけ）

  1. 相手から届いた公開鍵のファイル（例：receiver_public.asc）を、パソコンに保存します。
  2. Kleopatraで「インポート」を押し（図の①）、そのファイルを選びます。
  3. 一覧に相手の鍵が加わります（図の②）。この時点では「未証明」です。

2-5　指紋を確かめて、証明する（最初の1回だけ）

  1. 一覧で相手の鍵をダブルクリックし、詳細を開きます。
  2. 「フィンガープリント」（指紋）の40桁を表示します（図の①）。
  3. 相手に電話をかけ、相手の画面に出ている指紋を読み上げてもらい、1文字ずつ照合します。
  4. 一致したら、一覧に戻って相手の鍵を選び、「証明」を押します。自分の鍵で証明する画面が出るので、そのまま進めます。
  5. 一覧の表示が「証明済み」に変わります。

自分の指紋も、相手から聞かれたら同じ方法で読み上げます。

2-6　ファイルを暗号化する（送り手・毎回）

  1. 送るファイルを右クリックし、「署名して暗号化」を選びます（図の①）。
  1. 「署名する」にチェックを入れ、自分の鍵を選びます（図の①）。
  2. 「他の人のために暗号化」にチェックを入れ、受け手の鍵を選びます（図の②）。受け手が複数いる場合は、全員の鍵を追加します。
  3. 「パスワードで暗号化する」にはチェックを入れません。
  4. 「署名/暗号化」を押します（図の③）。自分の秘密鍵のパスフレーズを聞かれたら入力します。
  5. 元のファイル名の後ろに .gpg が付いたファイルができます。

「自分のために暗号化」について

ここにチェックを入れないと、暗号化したファイルを送り手自身は開けません。送ったものをあとで確認する必要がある場合は、チェックを入れます。

2-7　メールで送る（送り手・毎回）

  1. メールに、.gpg のファイルだけを添付します（図の①）。
  2. 暗号化前のファイルは添付しません。
  3. 本文には機密情報を書きません。本文は暗号化されないためです。
  4. パスワードを別のメールで送る必要はありません。開けられるのは受け手の秘密鍵だけです。

会社のメールの仕組みが .gpg の添付を止める場合があります。本番の前に、テスト用のファイルで一度往復させておくと安全です。

2-8　ファイルを復号する（受け手・毎回）

  1. メールから .gpg のファイルを取り出し、作業用のフォルダに保存します。
  2. Kleopatraで「復号/検証」を押し、そのファイルを選びます。右クリックのメニューからでも同じ操作ができます。
  3. 自分の秘密鍵のパスフレーズを入力します。
  4. 結果の画面で、「署名は有効」と表示されていること（図の①）、署名者が想定した相手であること（図の②）を確かめます。
  5. 「すべて保存」を押すと、元のファイルが取り出されます。

署名が無効、または署名者が違う場合

ファイルは使わず、送り手に電話で確認します。メールへの返信で確認しないでください。

  1. 件数や項目がそろっていることを確かめ、送り手へ「受け取って、開けました」と連絡します。

2-9　コマンドで行う場合（参考）

Gpg4winを入れると、コマンド プロンプトで gpg というコマンドも使えます。画面操作と同じことを、次のように行えます。メールアドレスとファイル名は例です。

作業コマンド
鍵ペアを作るgpg --full-generate-key
公開鍵を書き出すgpg --armor --export sender@example.com > sender_public.asc
相手の公開鍵を取り込むgpg --import receiver_public.asc
指紋を表示するgpg --fingerprint receiver@example.com
相手の鍵を証明するgpg --lsign-key receiver@example.com
署名して暗号化するgpg --encrypt --sign --recipient receiver@example.com --output file.csv.gpg file.csv
復号して署名を確かめるgpg --output file.csv --decrypt file.csv.gpg

復号したときに「Good signature from …」と表示されれば、署名は有効です。

2-10　止まったときの対処

状況原因対処
暗号化の画面で、受け手の鍵が選べない相手の公開鍵を取り込んでいない、または期限切れ2-4をやり直す。期限切れなら、相手から新しい公開鍵をもらう
「この鍵は証明されていません」という警告が出る指紋の確認と証明が済んでいない2-5を行う
復号できない（秘密鍵が無いと表示される）送り手が、別の鍵で暗号化した送り手に、どの公開鍵で暗号化したかを確認する
パスフレーズが通らない入力の誤り、またはキーボードの入力モードの違い半角英数になっているか確かめる。思い出せない場合、その秘密鍵は使えない
メールが届かない、添付が消えるメールの仕組みが .gpg を止めている情報システム部門に相談する。またはSFTPを使う

3後半：SFTPで送る

SFTPは、暗号化された通り道でファイルを送る方法です。メールより大きなファイルを扱え、送り先を決まったサーバーに限定できます。ここでは、受け手がSFTPサーバーを用意し、送り手がそこへ接続する形を例にします。

3-1　事前に相手と決めること

項目内容
ホスト名接続先のサーバーの名前（例：sftp.example.com）
ポート番号通常は22
ユーザー名サーバー側で用意してもらう接続用の名前
認証の方法SSHの鍵を使う方法を勧めます。パスワードだけの方法は避けます
置き場所ファイルを置くフォルダ（例：/upload）
接続元の制限送り手の会社のIPアドレスだけを許可してもらう
サーバーの指紋サーバーのホスト鍵の指紋。初回接続のときに照合する

3-2　ソフトを入れる（最初の1回だけ）

  1. 公式サイト https://winscp.net/ から、WinSCPのインストーラーをダウンロードして実行します。
  2. 鍵を作る道具（PuTTYgen）も一緒に入ります。

3-3　接続用のSSH鍵を作る（送り手・最初の1回だけ）

ここで作るSSHの鍵は、PGPの鍵とは別のものです。接続してよい相手かを確かめるために使います。

  1. WinSCPのログイン画面で「ツール」→「PuTTYgenを実行」を選びます。
  2. 鍵の種類を選び、「生成」を押します（図の①）。画面の指示に従って、マウスを動かします。
  3. 鍵のパスフレーズを2回入力します（図の②）。
  4. 「秘密鍵を保存」を押し（図の③）、決められた場所に保存します（例：C:\sftp_keys\sender_sftp.ppk）。
  5. 上の枠に表示された公開鍵の文字列をすべてコピーし（図の④）、相手に渡します。相手がそれをサーバーに登録します。

渡すのは公開鍵だけ

保存した秘密鍵のファイル（.ppk）は、相手に渡しません。

3-4　接続先を登録する（送り手・最初の1回だけ）

  1. WinSCPを起動し、「新しいサイト」を選びます。
  2. 転送プロトコルで「SFTP」を選びます（図の①）。
  3. ホスト名とポート番号を入れます（図の②）。
  4. ユーザー名を入れます（図の③）。パスワードの欄は空のままにします。
  5. 「設定」を押します（図の④）。
  1. 左の一覧で「SSH」→「認証」を選びます（図の①）。
  2. 「秘密鍵」の欄で、3-3で保存した秘密鍵のファイルを選びます（図の②）。
  3. 「OK」を押し、元の画面で「保存」を押します。

3-5　初めて接続する（送り手・最初の1回だけ）

  1. 「ログイン」を押します。
  2. 初回は、サーバーの指紋を確認する画面が出ます（図の①）。
  3. 事前に相手から聞いた指紋と一致することを確かめてから、「承認」を押します。
  4. 鍵のパスフレーズを聞かれたら入力します。

指紋が違う場合、2回目以降に同じ警告が出た場合

接続せず、相手に電話で確認します。別のサーバーにつながっている可能性があります。

3-6　ファイルを送る（送り手・毎回）

  1. 先に、2-6の手順でファイルをPGPで暗号化します。
  2. WinSCPで接続します。左が自分のパソコン、右がサーバーです。
  3. 右側で、決められた置き場所のフォルダを開きます。
  4. 左側の .gpg のファイルを、右側へドラッグします（図の①）。
  5. 右側に、同じ名前、同じサイズで表示されることを確かめます（図の②）。
  6. 接続を切り、相手に「置きました」と連絡します。

3-7　ファイルを受け取る（受け手・毎回）

  1. サーバーからファイルを取り出します。
  2. 2-8の手順で復号し、署名を確かめます。
  3. 取り出したあと、サーバーに残ったファイルを削除します。サーバーに置いたままにしません。
  4. 送り手へ受領の連絡をします。

3-8　コマンドで行う場合（参考）

Windowsのコマンド プロンプトで、次のように行うこともできます。この形で使う秘密鍵は、OpenSSHの形式で作ったものです（WinSCP用の .ppk とは形式が違います）。

作業コマンド
SSH鍵を作るssh-keygen -t ed25519 -f sender_sftp -C sender-sftp
接続するsftp -i sender_sftp sender_upload@sftp.example.com
置き場所へ移るcd /upload
ファイルを送るput data.csv.gpg
一覧を確かめるls -l
終了するbye

3-9　止まったときの対処

状況原因対処
接続できない（時間切れ）接続元のIPアドレスが許可されていない、または社内の通信制限相手に許可の状況を確認する。社内の情報システム部門にポート22の通信を確認する
「サーバーが鍵を拒否しました」と出る公開鍵がサーバーに登録されていない、またはユーザー名が違う相手に、渡した公開鍵の登録とユーザー名を確認する
ホスト鍵が変わったという警告が出るサーバーの入れ替え、または別のサーバーへの接続接続せず、相手に電話で確認する
アップロードできない（権限がない）置き場所のフォルダが違う決められたフォルダを開いているか確かめる

4運用ルール

  • 中身はPGP、通り道はSFTP。SFTPで送るときも、PGPの暗号化は省きません。
  • 鍵は業務用にする。個人名の鍵ではなく、窓口の名前と共有アドレスの鍵を使います。
  • 秘密鍵の置き場所を決める。使えるパソコンと担当者を限定し、控えを安全な場所に保管します。
  • 有効期限の前に更新する。期限の1か月前を目安に、新しい公開鍵を相手と交換し、指紋を確かめ直します。
  • 担当者が替わったら見直す。秘密鍵やパスフレーズを知る人が離れた場合は、鍵を作り直します。
  • 漏れた疑いがあれば失効させる。秘密鍵が漏れた、または失った場合は、すぐに相手へ連絡し、その鍵を使わないようにしてもらいます。
  • 記録を残す。いつ、誰が、どのファイルを、誰に送ったかを記録します。
  • 終わったら消す。受領の確認が済んだら、作業用のフォルダ、メール、サーバーに残ったファイルを削除します。
