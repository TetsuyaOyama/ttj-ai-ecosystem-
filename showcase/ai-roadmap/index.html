    段階 1　プロンプトの基礎

    段階1所要 約30分

    この章で分かること

    1. プロンプトを整えるとは、依頼に何を書き足すことかを説明できる。
    2. 段階 1 の 4 つの教材の特徴の違い（手を動かせる、短い、調べながら読める、別のモデルの見方）を言える。
    3. 段階 1 を終えてできることと、段階 2 へ進む目安を、自分の言葉で確かめられる。

    前提：序章と第 01 章。教材によっては、Python の基礎か、AI のサービスを試せる環境が要ります。

    プロンプトとは、何を整えるのか

    プロンプトエンジニアリング（prompt engineering）は、AI に出す依頼を、望む答えが返りやすい形に整えることです。依頼が整っていないと、AI は、足りない部分を推測して答えます。推測が外れると、望まない答えになります。

    次の表は、あいまいな依頼と、整えた依頼を並べたものです。例は、この講座が作った架空の例です。Google の Gemini API のドキュメントは、プロンプト設計の項目を挙げています。明確で具体的な指示、少数の例、文脈の追加、プロンプトの分解、試して直す方法です（出典：Google『Prompt design strategies』、確認 2026 年 11 月）。表は、そのうち 4 つを使いました。

    表で確かめる点は 3 つです。1 つ目は、整えた依頼が、誰が読むか（文脈）と、条件と、出力の形を書いていることです。2 つ目は、例を見せると、望む形が伝わりやすくなることです。3 つ目は、整えるのは、依頼を長くすることではなく、足りない情報を書き足すことだという点です。

    段階 1 の教材

    段階 1 の教材は 4 つあります。表の行を押すと、学べること・所要の目安・日本語・注意・確認の経路が出ます。

    表の「料金の札」と「状態の札」は、第 01 章の意味で読みます。確認日は、いずれも 2026 年 11 月 15 日です。

    どれを選ぶか：内容の特徴で決める

    この道筋では、次の順に並べました。順の理由は、教材の内容の特徴です。優劣ではありません。

    • Anthropic Prompt Engineering Interactive Tutorial：例を試しながら進める形式の教材です。手を動かせるのが特徴です。状態の札は「現行」で、9 章と付録の構成です。ただし、最後の更新は約 2 年前で、README は Claude 3 Haiku を使うと書いています。考え方は今も使えますが、モデル名や画面は読み替えが要ります。
    • DeepLearning.AI の講座：全体が 1 時間 40 分と、短い講座です。動画とコード例で進みます。Python の基礎が前提です。
    • Prompt Engineering Guide：プロンプト、コンテキストエンジニアリング、RAG、エージェントを扱うガイドです。テーマごとに必要な所を拾い読みできる形です（About ページの説明による）。
    • Gemini API のドキュメント：Google の公式ドキュメントです。別のモデルの見方を知りたいときに、読み比べに使えます。

    1 つだけ選ぶなら、まず、手を動かせる 1 つ目か、短い 2 つ目です。Python を使わずに考え方だけ知りたいなら、3 つ目か 4 つ目を、読み物として使えます。

    終えるとできること（段階 1）

    この段階の教材を 1 つ終えると、次のことに取り組めるようになります。保証ではなく、目安です。

    • 依頼に、目的・条件・出力の形・例を、書き分けられる。
    • AI の答えが望みと違うとき、依頼のどこを直せばよいかを、仮説として立てられる。
    • プロンプトの書き方を、ほかの人に説明できる。
    次へ進む目安

    自分の仕事や勉強の依頼を 1 つ選び、あいまいな依頼と、整えた依頼の両方を AI に出して、答えを見比べられたら、段階 2 へ進みます。見比べたときに、どの項目を足したのかを説明できると、目安を満たしています。

    段階 3　エージェント

    段階3所要 約35分

    この章で分かること

    1. AI エージェントの動きを、「考える → 道具を使う → 結果を見る → 繰り返す」の流れで説明できる。
    2. 段階 3 の 5 つの教材の特徴と、前提・費用（API キー、アカウント）の違いを言える。
    3. 「ここまでで実用的」の区切りの位置を言い、段階 4 へ進む目安を確かめられる。

    前提：第 03 章（段階 2）。教材の多くは、Python の基礎が前提です。

    エージェントとは

    AI エージェント（AI agent）は、道具を使って作業を進める AI です。質問に 1 回答えて終わるのではなく、自分で次の動きを決め、道具を使い、結果を見て、また次を決めます。

    Hugging Face の講座は、エージェントの基礎として、ツール、思考、行動、観察を挙げています（出典：Hugging Face『Agents Course』、確認 2026 年 11 月）。次の図は、その流れを、この講座がまとめたものです。ツール利用（tool use）は、AI が検索や計算などの外部の道具を呼び出して、結果を使うことです。

    図で確かめる点は 3 つです。1 つ目は、「考える → 道具を使う → 結果を見る」の繰り返しです。2 つ目は、答えが出たら終わる、終わる条件があることです。3 つ目は、繰り返しに回数の上限を決めておくことです。上限がないと、終わらずに、API の利用料が増えることがあります。

    段階 3 の教材

    段階 3 の教材は 5 つあります。Anthropic の Cookbook は、Claude Cookbooks に改名されています。表の行を押して、前提と注意を確かめてください。

    用語を 3 つ整理します。MCP（Model Context Protocol）は、AI アプリを外部のデータやツールにつなぐための、オープンソースの標準です。ノートブックは、説明とコードを 1 つの文書にまとめたものです。RAGは、第 02 章の用語です。外部の資料を検索して、答えに使います。

    どれを選ぶか：内容の特徴で決める

    Hugging Face の講座、Microsoft の講座、Cookbook、MCP の入門の順に並べました。並べた理由は、内容の特徴です。優劣ではありません。

    • Hugging Face の Agents Course：単元が順に並び、無料で、修了の条件が書かれています。週に 3〜4 時間という設計が、ページに書かれています。
    • Microsoft の AI Agents for Beginners：レッスンが 18 本で、設計パターンから、運用、セキュリティまで幅広く扱います。日本語訳があります。
    • Claude Cookbooks と OpenAI Cookbook：作り方の例を集めたものです。通して読む講座ではなく、必要なレシピを拾って使います。API キーが要る場合があります。
    • MCP の入門：短い説明のページです。エージェントを外部の道具につなぐ標準を知る入口になります。
    ここが「実用的」の区切りです

    この道筋は、段階 1 をしっかりやり、この段階の Hugging Face の講座あたりまで進めば、実用の入口に立てる、と考えます。目安で、保証ではありません。ここで止めても構いません。段階 4 は、複数のエージェントを実際に動かしたい人が選びます。

    終えるとできること（段階 3）

    この段階の教材を 1 つ進めると、次のことに取り組めるようになります。保証ではなく、目安です。

    • エージェントの動きと、終わる条件・回数の上限の必要さを説明できる。
    • ツール利用、RAG、MCP の言葉を、簡単な例とともに説明できる。
    • 自分の作業の中から、エージェントに任せやすい作業と、任せない作業を分けられる。
    次へ進む目安

    小さな作業を 1 つ選び、AI に任せる手順と、自分で確かめる手順を、紙に書けたら、段階 4 へ進みます。動かす経験は、段階 4 で積めます。

    つまずきやすい点

    教材の料金と、API の利用料を混ぜることです。Hugging Face の講座は、無料で認定も無料と書いています。ただし、動かすときに使うモデルの API の利用料については、ページに記載がありません。Cookbook は、API キーが前提です。

    もう 1 つは、API キーの扱いです。API キーは、他人に見せません。ノートブックやコードに直接書いて、公開のリポジトリに載せると、他人に使われることがあります。

    段階4所要 約35分

    複数のエージェントを動かす枠組み

    マルチエージェント（multi-agent）は、役割の違う複数のエージェントを組み合わせて、1 つの作業を進める方法です。たとえば、調べる役、まとめる役、確かめる役、のように分けます。

    この方法を実際に動かすには、フレームワーク（framework、部品と使い方の枠組み）を使います。段階 4 では、フレームワークを選んで、動くサンプルを試します。

    この道筋の元の案では、「CrewAI か Microsoft AutoGen」でした。このうち AutoGen は、アーカイブされ、保守が終わっています。新規には、Microsoft Agent Framework が案内されています。AutoGen は、状態の札を付けて、表に残しました。

    AutoGen と、後継の Microsoft Agent Framework

    AutoGen の README は、プロジェクトがアーカイブされ、Microsoft による保守は終わったと書いています。バグやセキュリティの修正も、新機能も、サポートも提供されません。本番での利用は勧められていません。リポジトリは、歴史と参照のために公開が続いています（出典：Microsoft『AutoGen』README、確認 2026 年 11 月）。

    Microsoft Agent Framework の Learn のページは、AutoGen と Semantic Kernel の直接の後継と書いています。AutoGen からの移行ガイドも、用意されています（出典：Microsoft Learn『Microsoft Agent Framework overview』、ページ表示の更新日 2026 年 10 月 28 日）。
